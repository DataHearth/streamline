# Streamline

Unified media management platform replacing the *arr stack (Radarr, Sonarr, Lidarr, Readarr) and Seerr. Single self-hosted binary with a slick web UI, REST API for mobile developers, multi-user support with SSO, built-in request system, and automatic media organization. Supports Torznab and Prowlarr indexers, torrent download clients (qBittorrent, Transmission, Deluge, or the built-in engine), and media server notifications (Plex, Jellyfin, Emby). Shipped v1.0.0; music and books are in progress (phase 1, library management, landed for both), a player is planned (`docs/wiki/Roadmap.md`).

## Stack
- Go monolith: chi + oapi-codegen (OpenAPI → server) + ent ORM + modernc.org/sqlite (CGO-free)
- Config: koanf (file + env + flags, STREAMLINE_ prefix)
- Logging/Observability: slog + OpenTelemetry (traces, metrics, logs via OTel bridge)
- Frontend: Svelte 5 SPA (TypeScript) — Routify v3 file-routing, TailwindCSS v4, TanStack Query + TanStack Form, valibot schemas; bundled by esbuild, embedded via go:embed

## Frontend

Svelte 5 SPA in `web/app/` (TypeScript everywhere), Routify v3 file-routing over `web/app/routes/`, TanStack Query + Form, valibot, TailwindCSS v4, bundled by esbuild and `//go:embed`-ed. A section's wrapping layout MUST be `_module.svelte` — `_layout.svelte` renders as a sibling route, not a wrapper. Both library lists paginate server-side, and their toolbars read **faceted** counts — each facet counted against the *other* filters, each with its own `*_total` "all" row. Settings pages pick save-per-control **or** one TanStack form, never both on a page, and either way the page must call `markConfigForm()` or nothing on it locks on a read-only instance.

**Conventions, the dropped facets, search folding, the PWA surface and the bundling pipeline: [`docs/agents/frontend.md`](docs/agents/frontend.md) — read it before touching `web/app/**` or `web/embed.go`.**
## Logging
- No `*slog.Logger` plumbing. `cmd/main.go` calls `observability.Setup` then `slog.SetDefault`; every package logs via `slog.XContext(ctx, ...)` (top-level) — never hold a logger field.
- `observability.Setup` returns one `slog.Handler` = `contextEnrichingHandler(multiHandler{stderr, otelslog.Handler})`. stderr is pretty text/json from `log.app.{level,format}`; otelslog bridges to the OTLP logs pipeline (traces/metrics/logs all batch-exported to `otel.endpoint`).
- **`log.app.enabled` gates the stderr sink only**; the OTel pipeline is gated on `otel.endpoint` alone. It used to return early with a `DiscardHandler`, so quieting local logs silently stopped traces and metrics as well — an instance exporting nothing, for a reason nowhere near the OTel config.
- `contextEnrichingHandler` auto-attaches `request_id` (chi), `user.id`/`user.email`/`user.roles` (auth claims, OTel semconv v1.40.0), `http.route` (chi route pattern). Trace/span IDs come from otelslog. Use `slog.XContext` so ctx flows through.
- On an authenticated request `user.*` is therefore the **caller**. A log line about another account (admin CRUD, unlock, session revoke) names it `target.user.*` — writing `user.id` there emits the key twice, target and actor, and a filter on `user.id` matches both people.
- `observability.LevelCritical` (= `slog.LevelError + 4`, rendered `CRITICAL`) for panics, invariant violations, unrecoverable conditions. Call via `slog.LogAttrs(ctx, observability.LevelCritical, ...)`.
- OTel semconv pinned at v1.40.0 — use `semconv.<Key>Key` constants (e.g. `semconv.HTTPRouteKey`) over string literals; keep versions aligned across files.

## Observability
- `internal/otelx` is the leaf OTel helper package. Holds `HTTPClient` (otelhttp-wrapped — use for every outbound HTTP call; never `http.DefaultClient`; every response body is capped at `MaxResponseBody` inflated bytes, a backstop against a hostile remote's gzip bomb, so a caller streaming something larger needs its own client; a call that knows its answer is small decodes through `otelx.DecodeJSON(body, max, out)` with a per-package ceiling) and `RecordSpanError(span, err) error` (inline: `return ..., otelx.RecordSpanError(span, err)` — no named returns). Must stay dependency-free; `internal/observability` imports `internal/auth`, so anything auth transitively uses must live in `otelx` not `observability`.
- Per-package tracer: `var tracer = otel.Tracer("github.com/datahearth/streamline/internal/<pkg>")`. Span names `<pkg>.<op>` (e.g. `download.grab`, `rss.process_movie`, `indexer.query`).
- DB auto-instrumented via `otelsql.Open` + `RegisterDBStatsMetrics` in `internal/db/client.go`. Add business-logic spans in service methods + `span.SetAttributes` for domain context.
- Prefer semconv helper funcs (`semconv.UserEmail`, `semconv.UserRoles`, `semconv.UserID`, `semconv.DBSystemNameSQLite`) over raw `attribute.String("user.email", …)`.
- **Never put a row id in a metric attribute** — `movie.id`, `episode.id`, a request path with an id in it. That is one time series per row in the library. Ids belong in the log line and on the span; a metric attribute is a low-cardinality dimension (`outcome`, `kind`, `status`, an indexer or client *name*).
- **A span that can fail must record the failure.** Every terminal path funnels its error through `otelx.RecordSpanError` or, where a helper owns the exits, through one choke point (`transcoding.record`, `scheduler.executeJob`). A span left untouched by its own failure paths reports OK, and filtering a backend for error spans then finds nothing wrong.
- **Every goroutine started with `go` defers `observability.RecoverPanic(ctx, what, onPanic)`.** `middleware.Recoverer` covers the request path and nothing else; an unrecovered panic in a background worker takes the whole process down. `onPanic` is the caller's policy — a scheduled job records `errJobPanicked` and retries next tick, a transcode fails terminally, a boot goroutine calls `stop()` for a clean shutdown.
- Sampling is `otel.sample_ratio` (default `0.05`), overridden by `OTEL_TRACES_SAMPLER` — `Setup` skips its own `WithSampler` when that variable is set, because passing the option at all makes the SDK ignore the env. `otel.insecure` is needed for an `http://` collector; `otel.environment` fills `deployment.environment`.
- `otel.SetErrorHandler` routes SDK export failures into the stderr handler **only** — never the full handler, or a failing log exporter is fed its own error records.

## HTTP Routes
- `/health` — pre-auth bare JSON endpoint (NOT in OpenAPI), for k8s probes + load balancers. Registered in `internal/server/server.go`.
- `/api/docs` — Scalar UI shell (`web.Handler.APIDocs`). `/api/v1/openapi.yaml` — embedded spec. REST API mounted via `restapi.Mount`.
- SPA fallback: `s.router.NotFound` → `web.Handler.SPAShell`, which writes the embedded `web/app/index.html` for every non-API, non-static path; Routify owns client-side routing incl. its own 404. Static assets served at `/static/*` from `fs.Sub(web.Assets, "static")` (wired in `web.Mount`).
- `/rest` (Subsonic, `subsonic.Handler.Routes`) and `/opds` (`opds.Handler.Router`) are mounted in `server.New` beside `/posters`, NOT in OpenAPI, and authenticate themselves (Subsonic from the query, OPDS by Basic with the per-user `OpdsToken`, stored as a SHA-256 hash and compared in constant time). A successful call of either stamps `last_used_at`/`last_client` through `internal/appaccess` (debounced to one off-request write per user and kind per 5 minutes, guarded on the credential's `*_created_at`). Logging and the body cap still apply. OPDS cover links point at `/posters/*`, which stays behind the session middleware, so Basic-auth readers get no thumbnails.
- `/posters/{kind}/{id}/poster.jpg` — poster proxy via `s.posters.Serve`; `kind` is `movies`, `tvshows`, `artists`, `albums`, `books` or `authors`.
- `/posters/lookup/{kind}/{key}/poster.jpg` — the **only** proxy for art of a title that is not in the library (`internal/artwork`, behind the session middleware, not in OpenAPI): `kind` is `artists` or `albums` (an MBID, the latter a release-group) or `books` (a Hardcover book id), 404 means no art and the SPA draws its placeholder. The client never supplies a URL or a name: the lookup services remember the provider's own reference as they serve a payload (`artwork.Remember(kind, key, artwork.Source{URL | DeezerID | Name})`, a bounded in-memory map, 2000 entries, 24 h, lost on restart) and the proxy resolves from that — an artist through MusicBrainz's own Deezer link first, else a name search accepted only with **exactly one** hit that folds equal (a namesake gets no face rather than a wrong one), an album through the Cover Art Archive front, a book through the Hardcover image URL the payload already carried. It **never spends a MusicBrainz or Hardcover request**. Every fetched URL and every redirect hop must be https on `dzcdn.net`, `coverartarchive.org`, `archive.org` or `assets.hardcover.app`; a key that is already a library row serves that row's file instead; a copy older than 24 h is refetched (and served stale if the refetch fails); the on-disk cache under `posters/lookup/` drops its 200 oldest entries past 2000; a failed resolve is remembered for an hour in memory; concurrent requests for one key share one fetch. The metric label is `lookup-artists|lookup-albums|lookup-books` on the existing `streamline.posters.*` counters.
- `POST /api/v1/schedules/{name}/run` marks its run with `scheduler.Manual(ctx)`, and the throttled jobs waive their own windows on it — the missing searches take `unthrottledWindow()` (no cooldown, no failure cap), the metadata refreshes take a cutoff of now. Without it a manual run walked the list, touched nothing, and read as a trigger that did not fire.
- `GET /api/v1/schedules/events` is the one streaming endpoint: `text/event-stream`, a full `ScheduleList` frame on connect and on every `scheduler.Subscribe` nudge, coalesced to 250ms, keepalive comment every 15s. It is a strict-handler response type (`scheduleStream`) that writes the stream from its own `Visit` method, and it clears the listener's 2min `WriteTimeout` on its connection via `http.ResponseController` — nothing else may rely on that. A job reports progress with `scheduler.Progress(ctx, done, total)` on the ctx the scheduler handed it (a no-op on any other ctx); `total` 0 means "counting without a known size" and the SPA shows a bare count with no bar.
- `DELETE /api/v1/torrents/{hash}` also calls `downloads.PurgeRecordForHash`, dropping the live download record behind that torrent and reverting its media. The monitor's orphan sweep would eventually do it, but only after `monitorOrphanGrace` (2 min) — a window that exists to tolerate a client that hasn't caught up with its own listing, which a removal issued through streamline is not. The Torrents page invalidates `["activity","queue"]` on success for the same reason.
- The auth middleware's exclude list is the package-level `authExcludePaths` in `internal/server/wire.go`, handed to `middleware.NewAuth` (`/health`, `/api/docs`, `/api/v1/openapi.yaml`, `/static/`, `/login`, `/register`, `/auth/login`, `/auth/register`, `/auth/config`, `/auth/invite/`, `/auth/oidc/`, `/rest/`, `/opds`, `/opds/`); matcher in `internal/server/middleware/auth.go`, paths ending `/` match as prefix and everything else exactly, which is why OPDS needs both forms.

## Auth, sessions & OIDC

The middleware splits transport by path prefix: `/api/v1/*` takes Bearer, `X-API-Key`, or a same-origin `streamline_session` cookie; everything else is cookie-only and 302s to `/login`. API keys are read-only on the identity band. OIDC is multi-provider, and provider trust is **two independent axes** — `email_linking` (which accounts it may adopt) and `allow_admin` (whether it may grant admin).

`role.Federated` in `internal/role/` is the single admin ceiling, enforced by a package boundary that makes skipping it a compile error, plus type-resolved specs over package `auth`. **Never merge the two trust keys, never export the role field, never move the type back into `auth`** — four rounds of weaker guards were each bypassed.

**Linking policy, the API-key denial list, seed admin, registration modes and what the guards deliberately do not cover: [`docs/agents/auth-and-oidc.md`](docs/agents/auth-and-oidc.md) — read it before touching `internal/auth/`, `internal/role/`, or the auth middleware.**

## Config surface

Seven sections are readable and patchable at runtime (`/config/{auth,library,ffmpeg,download,metadata,system,transcoding}`, admin-only, partial-patch); everything else is file-only and needs a restart. The trust boundary and every secret are deliberately file-only — a key the API can reach is a key the API can be made to grant. Media servers, download clients, indexers and quality profiles live in the YAML config, name-keyed and hot-editable, not in ent/SQLite.

**Adding or removing a config field means `defaults()` AND `api/config.schema.json`.** Bounded ints go through `narrowUint8` and durations through `checkDuration` — both must reject *before* conversion, since nothing validates a request body against the spec.

**The full section-by-section rules and the resource CRUD contract: [`docs/agents/config-surface.md`](docs/agents/config-surface.md) — read it before touching `internal/config/` or the `/config/*` handlers.**

## Downloads, imports & adoption

The builtin engine owns its own peer sockets and caps its peer pool with constants (not config keys). Its limit enforcer only stops uploading; removing a seed-complete torrent **with its files** is the download manager's call on the monitor tick, and only for a builtin torrent whose record the importer already completed. The importer verifies a probed source against the release claim before any transfer and parks a failing record `held` rather than counting an attempt. Untracked torrents the clients report are matched against the library each monitor tick and either auto-imported or filed as a `pending` proposal. Every successful import, bulk-import commit, transcode swap, rename and file delete dispatches a media-server refresh — the last two through `mediaserver.RefreshInBackground`, off the request path.

A record is filed under one `anchor_episode` and links every episode its download is for through the `episodes` many-to-many (anchor included, upgrade targets too) — **every status write over that set filters on the status it moves from**, and every grab path links every episode it marks `downloading`, since the orphan sweep spares exactly what an in-flight record links.

**A record's `save_path` is derived, not reported.** Streamline never sends a save path on add — qBittorrent gets `category: "streamline"` and nothing else — so the location contract is `<library.download_path>/<torrent name>` and lives in the client's category configuration. **Adoption must therefore stat before it commits** (`adoptionPath`), falling back to the client's own `Torrent.SavePath` through `download.path_mappings` and filing a `pending` proposal when neither resolves: an unverified path reaches the importer as a *retryable* ENOENT, burns all `import_max_attempts`, and lands `failed`. `POST /activity/history/{id}/retry` is the only exit from `failed` — `resolve` takes `held` only and the importer's scan takes `importing` only.

**Engine internals, port rebinding, hold/resolve semantics, the adoption proposal lifecycle, the retry contract and Plex section discovery: [`docs/agents/downloads-and-imports.md`](docs/agents/downloads-and-imports.md) — read it before touching `internal/bittorrent/`, `internal/importer/`, `adopt.go`, or `internal/mediaserver/`.**
## Selective file download

`download.selective_files` (default **false**, runtime-toggleable) gates grabbing only the files a release is wanted *for*; off is bit-for-bit the whole-torrent grab. Two flows — a `.torrent` decodes the metainfo before add, a magnet parks the record `selection_state: pending` until `RunSelectionPass` resolves it. `replace_mode` decides the wanted set; `selection_mode` on `TorrentSession` is what survives a restart.

**Flow rules, per-client quirks and the widen semantics: [`docs/agents/selective-file-download.md`](docs/agents/selective-file-download.md) — read it before touching `internal/download/manager.go`, `selection_pass.go`, or any client's `SetWantedFiles`.**

## Quality scoring

`internal/quality` is the pure scoring engine (no config/db imports); context builders live in `internal/quality/qualityctx`. A release is gated by resolution **band** first (`preferred_resolution` is a hard ceiling), then by summed custom-format score against `min_score`. `quality.ReplacesFile` is the single predicate deciding whether one release replaces one file. Builtins describe a release and never judge one — opinionated rules belong in `custom_formats`.

Every `indexer.Manager` search takes **two name sets**: `titles` is queried (one request per title per indexer) and `aliases` is only matched against. `Movie.aliases`/`TVShow.aliases` hold the providers' translated and alternative titles, which is what stops a library holding a work under its localized title from discarding every release named in another language. **Never pass an alias list as `titles`** — that multiplies every search by its length against rate-limited trackers.

**Condition semantics, the release-vs-file evidence asymmetry, indexer result filtering, profile assembly and the upgrade paths: [`docs/agents/quality-scoring.md`](docs/agents/quality-scoring.md) — read it before touching `internal/quality/**`, the RSS scanners, or the profile/custom-format handlers.**

## Media lifecycle & library queries

Twelve optional probe columns hang off `MediaFile`; `probed_at` stamped means all twelve were recorded, so **a migration adding a probe column nulls `probed_at` in the same file**. `MediaEvent` has three optional owner edges and exactly one is set. `episode.status` is `wanted | downloading | importing | paused | available | skipped`, and every path that grabs must mark its episodes — **adoption included, which lands at `importing` and needs its own record-scoped mover** (`MarkWantedRecordEpisodesImporting`), since the completion sweep's one only moves `downloading`/`paused`. The series list filters, sorts and pages in SQL with a per-show counts rollup — never the episode tree — and derives a show's downloading/importing state from `episode.status`, so an unmarked episode is a show missing from those filters entirely.

An episode with no air date is **unaired, never missing**, and five places split aired from unaired — they must agree or a show matches a filter with nothing missing on its page. Specials (season 0) are out of every show-level number — seasons, episodes, the missing filter, the episode sort — and must be out of all of them at once; the specials season still renders with its own counts.

Cast is written inside the title's transaction; the **person biography fetch is not** — it runs after the commit, from the service layer that holds the providers, and `internal/db` stays free of any provider dependency. A person is enriched **once, ever**, keyed on `Person.details_fetched_at`, and no failure there may fail the import.

**Probe semantics, the event hooks, cast ingest and person enrichment, re-identify ordering, the in-flight marking paths and the list push-down: [`docs/agents/media-lifecycle.md`](docs/agents/media-lifecycle.md) — read it before touching status transitions, `internal/events/`, or `internal/db` list queries.**
## Music

Third vertical, mirroring the TV tree: `Artist → Album → Track`, with `MediaFile.track` as the file edge. Metadata is MusicBrainz (`metadata.NewMusicBrainz`, no key, a 1 req/s limiter and a mandatory User-Agent) and an album is a MB **release-group**; an album cover is resolved by `music.Service.resolveCover` (`covers.go`) from the first source that yields an image: a picture embedded in one of the album's files (`audiotags.Picture`), a `cover|folder|front.jpg|jpeg|png` beside the first media file, Deezer by the canonical release's barcode (`Album.barcode`, kept from MusicBrainz at add time; `metadata.NewDeezer`, keyless, 10 req/s), Deezer search (only when the first hit's artist matches, via `library.TitleMatches`), then the Cover Art Archive release-group front. Local sources store through `posters.Manager.Put` and run even when a cover is cached (the album's own art outranks a downloaded one); the remote ones only when none is, and a failing source falls through to the next. It runs in the background (`ResolveCoversInBackground`, behind the `music.CoverResolver` interface that bulkimport and the importer call after adoption/import) and never fails the add; `RefreshOne` re-resolves only albums with no cached cover. Span `music.resolve_cover` carries `cover.source`, counter `streamline.music.cover_resolutions{source}`. Library covers go through the posters proxy under the `albums` kind and artist photos under `artists` (a monogram when there is none). `Add` is **two-phase** (below): the request fetches only the artist and its release-group list and returns album stubs; a background worker fills the tracks. `Track.duration` is **seconds** (MusicBrainz reports milliseconds; the client divides) and the spec, SPA and ent field all agree on that. Music profiles are their own config family, `music_quality_profiles[]` + `music_quality_default_profile`, edited through `/music/quality-profiles` (never `/config/*`; the first profile created becomes the default, `POST …/{name}/default` moves it). A profile ticks **tiers** (`hires > lossless > high > standard > low`, stored best first) and names the `preferred` one, the upgrade ceiling; there is no `other` tier. `internal/quality/audio.go` is the one classifier (`AudioTierOf`, `AudioFine`, `MusicProfile.Accepts/Score/Replaces`), and the SPA's `releaseTier()` is written to the same rule. `library.ParseMusicRelease` reads codec, bit depth, sample rate, rate and VBR preset into `Facts` plus the display label `Source` (`FLAC 24/96`, `MP3 V0`); `JudgeMusicRelease`/`ScoreMusicRelease` take a `MusicScope` (a discography is rejected for an album search and kept for an artist-level one) and a release whose name states no quality stays in the list, rejected, instead of landing in a catch-all tier. `MediaFile.quality` is the tier (`hires|lossless|high|standard|low`, empty when it could not be established), `format` the extension. Album art for a title **not in the library** (the add flow, a request panel) comes from the one lookup proxy, `GET /posters/lookup/{artists|albums|books}/{key}/poster.jpg` (`internal/artwork`, see HTTP Routes); artist photos in the library are the `artists` poster kind. `POST /music/albums/{id}/search` and `/grab` are the manual search and grab (member-only; the grab body is a search item's `release` handle intact, answered with an empty 202). `GET /music/artists` is filtered, sorted, paged and faceted in SQL (`/music/artists/counts`, the faceted-counts convention of `/series/counts`) and its items carry their albums as tiles with no tracks; the detail, patch and refresh responses carry the full tree.

Phases 2–6 landed backend-only (the SPA for them is in progress). **Adoption** is `ImportScan.kind=music` through bulkimport: every folder directly holding audio files is one candidate, tags are read with `internal/library/audiotags` (dhowden/tag, never writes), the majority `(albumartist|artist, album)` pair is matched through `MusicProvider.SearchReleaseGroups`, and commit adopts in place (`source=orphan`) after seeding the artist through `music.Service.Add` with `Monitor: "none"`; `mode=rename` is refused (`ErrRenameUnsupported`, 422), a release group missing from the artist's discography fails that album with a message, a disc subfolder is its own candidate, and `AdoptAlbumFiles` never moves an album out of `downloading`. There is **no media-server refresh** for music — `Dispatcher.RefreshAll` only knows movie and series sections. **Subsonic** is `internal/server/subsonic` at `/rest` (API 1.16.1, opaque ids `ar-/al-/tr-`, raw streaming only, cover art straight from the posters service), authenticated against `User.subsonic_password` — generated by `/account/subsonic-password`, stored recoverable because the token scheme is `md5(password+salt)`, never valid for web or REST auth; non-API errors are logged before the generic error-0 envelope. **Acquisition**: `library.ParseMusicRelease`/`ScoreMusicRelease` (tiers, discographies rejected for an album scope), `indexer.Manager.SearchAlbum` (cat 3000), `music.Service.SearchAlbumReleases`/`GrabAlbumRelease` over `download.GrabAlbum`, which links the record's `album` edge; `Store.SetAlbumStatus` and `RecordAlbumImportSuccess` filter on the status they move from. The album importer (`importer/album.go`) matches files to tracks by tagged `(disc, track)` then title, renames per `library.music_naming` (`{Artist}` `{Album}` `{Disc}` `{Track:02}` `{Title}` `{Year}`) and writes corrected tags plus MusicBrainz ids on the **library copy** — so `hardlink`, and `move` with `keep_torrent_seeding`, are forced to `copy`, since writing through the seeding inode would corrupt the torrent. **Automation**: `rss/music_feed.go` gates on 3000–3999 *after* 3030 (audiobooks) is carved out, `SearchMissing` and `RefreshStale` (10 artists per run) hang off the existing missing-search and metadata-refresh jobs. **Requests**: `media_type` artist carries `media_mbid` with `media_id=0` (album and author requests no longer exist); the active-uniqueness index is partial per key (`media_id <> 0` / `media_mbid <> ''`); approving an artist adds it monitored `all` under the reviewer's profile, and the request flips to `available` on the artist's first imported album (`MarkRequestsAvailableByMBID`), not when the discography is complete.


**The music design backend** (contract `docs/superpowers/specs/mb-design/contract-music.md`). **`Add` is two-phase:** it costs `1 + ceil(n/100)` MusicBrainz calls (a 10-minute, singleflight, 32-entry `ArtistDetails` cache shared with `GET /music/search/{mbid}`, so a lookup followed by an add costs one set), creates the artist, its `ArtistMember` rows and one stub `Album` per release group in one transaction, and returns with `hydrating: true`. `music/hydrate.go` then fills each album — tracks, label, country, media, bonus/featuring flags, and, when the heavy release call (`inc=…artist-rels+recording-level-rels+work-rels+work-level-rels+place-rels`, response cap `maxMusicReleaseResponse` 8 MiB) succeeds, credits, performers, writers and studio. A failed heavy call retries once with the light `recordings+artist-credits+labels` inc and stamps `metadata_fetched_at` but not `credits_fetched_at`; the credits sweep (`RefreshStale`, 20 a tick, releases above `db.MaxCreditsTracks` skipped) retries it later. **`metadata_fetched_at` NULL is the one "tracks not here yet" marker**: `tracks_pending` on a tile, `HydrateAlbum` (the synchronous, idempotent entry the album importer and bulk-import adoption call before matching files to tracks, also removing the album from the queue), the sweep, and the eligibility predicates all key on it — `ListEligibleAlbumsForSync` and `ListWantedAlbums` skip an unhydrated or **unreleased** album (the music twin of "unaired is never missing"; an undated album is released, and `upcoming` is derived from a wanted album dated after today, never stored). The worker is one process-wide goroutine behind `defer RecoverPanic` (its `onPanic` resets the queue, or the dead worker's albums would stay marked queued forever), serves one album per artist in turn, monitored and newest first, backs off for a `Retry-After` and refills from the database when idle (restart recovery, plus `ResumeHydration` at boot). **Two MusicBrainz classes share the one 1 req/s limiter** (`metadata/mblimiter.go`): an interactive caller takes the next token; a context marked `metadata.Background(ctx)` (the worker, the credits sweep, the scheduled refresh) takes one only while no interactive caller waits and not within `musicBackgroundGap` (2 s) of its last, so bulk hydration is about 4 s per album and a lookup never queues behind it. A 503 from MusicBrainz is `*metadata.RateLimitedError` (`Retry-After`, a minute when absent), which the handlers answer as `429 rate_limited`. `hydrating` stays true only while an album has no tracks, or has tracks whose credits are missing and landed under an hour ago and fit the sweep's size cap, so the SPA does not poll for a day over a release whose heavy call keeps failing.

**Monitoring is a policy** (`Artist.monitor` all/future/manual/none, `monitored` is gone): `PATCH` re-applies it to the existing albums in one transaction and never touches `status`; new release groups on add and refresh follow it (`future` = undated or dated after today); `Album.monitored` stays the only flag searches, RSS and imports read. The artist `status` rollup (`wanted|downloading|available`) is over monitored, non-upcoming albums and has a SQL twin (`db.artistStatus`) that the list filter and the facet counts use — keep the two in step. **The overview is Wikipedia in both SPA locales**, fetched once (`details_fetched_at`; a refresh re-fetches only an empty English one) from the Wikidata item MusicBrainz links, stored as `overview`/`overview_source` (en) and `overview_fr`/`overview_source_fr`, served for `?lang=` with English as the fallback and the source following the text actually served. The **artist photo** is Deezer by MusicBrainz's own link, else by name only when exactly one hit folds equal to it (never "first hit wins"), stored under the `artists` poster kind; lookup art for hits not yet added is `internal/artwork`'s, fed by `artwork.Remember` from `SearchArtists` and `LookupArtist`.

**Searches and packs.** `POST /music/albums/{id}/search` keeps every release the profile rejects, flagged with a reason ("tier not in the profile", "quality is not stated in the release name") and drops a discography (rejected by scope, not listed); `/music/artists/{id}/browse` is the inverse — only discographies whose artist part (`library.SplitCreatorTitle`) folds equal to the artist. `search-now` on an album/artist/track is a 202 that runs `searchAlbum` in a goroutine (waiving the cooldown and failure cap by not consulting them; an available, upcoming or in-flight album is a no-op). **A discography pack is a `DownloadRecord` with an `artist` edge and the albums it expects on the `albums` many-to-many** (`download.GrabArtistPack`: it links monitored, released, hydrated, wanted-or-paused albums, refuses with `ErrNoWantedFiles` before touching the client when none qualify, and marks them `downloading`); `importer/pack.go` groups the audio files by folder (a `CD1`/`Disc 2` subfolder belongs to its parent), matches each folder to a **linked** album by folded title and, when it names one, year — no provider call — and runs the ordinary album import for each with `KeepRecord`, then `CompletePackRecord` completes the record and returns the linked albums no folder named to `wanted` with no strike. Rename (`music.Renamer`, `library.Renamer` keyed by artist) renders `library.music_naming` with the importer's own helper from database metadata only; `DELETE /music/tracks/{id}/file` checks every path against `library.music_path` first (`409` if any lies outside, nothing deleted) and moves a `available` album to `wanted`.

## Books

Fourth vertical, **book-first**: `Book` is the root entity and a shelf item on its own, or a volume of a `BookSeries` (`ShelfItem = Book | BookSeries`; a volume is never a shelf item). People are slim `Author` rows (name, sort name, photo source) joined to a book *or* a series through `BookContribution` (`role` author/writer/artist/colorist/cover/translator/narrator, `language` on a series translator; exactly one owner is set, enforced by the writer like `Credit`). **There is no author-follow**: nothing is monitored per author, `/books/authors*` and the `author` request type are gone, and an `Author` with no contribution left is deleted in the same transaction as the book or series that orphaned it. `Book.author_name` is the display string (authors, else writers, else artists, joined with ` & `, three then ` et al.` — `pick.DisplayAuthor`) and what the naming `{Author}`, OPDS filenames and the indexer query read.

A book carries two independent **slots**, ebook and audiobook, each with its own `*_monitored`/`*_status`/`*_grab_failures`/`*_last_search_at`, a `*_edition` pointer and a `*_replacing_language`; `MediaFile.book_kind` says which slot a file fills. Slot state on the wire is derived (`book.SlotState`, mirrored by the shelf SQL — change one and the other): unmonitored iff not monitored and neither available nor downloading, a paused record is `downloading`, a monitored `wanted`/`skipped` slot is `wanted`. A book's status ignores unmonitored slots and reports `available` until its release date (an unreleased book is never a wanted slot — `ListWantedBooks`, `SearchMissing`, `search-now` and RSS all require `last_refreshed_at IS NOT NULL` and `release_date IS NULL OR <= now`); a series' status looks at its hydrated, released volumes' **ebook** slot only.

**Editions**: `BookEdition` keeps the best Hardcover edition per `(language, publisher, format)` (≤ 40 per book, the winner of every `(language, format)` pair always kept; `metadata.SelectEditions`, pure — a paperback counts as an ebook only for a language with no digital ebook, which is how a comic gets one). A slot points at one; a row a slot points at is **never pruned**, so `edition_id` is stable across refreshes. `internal/media/book/pick` is the shared pure rule set for the database layer and the service: slot pick (preferred language → original → most popular), title derivation (best edition in `preferred_language`, ebook before audiobook, else the original's, else Hardcover's) and the series monitor policy. `Book.title` is never tied to a slot's edition. A **refresh fills a slot that has no edition but never re-points one that has** (a hand-picked edition survives it); `PATCH preferred_language` re-picks every slot without a file; `PATCH format+edition_id` on a slot *with* a file stores `*_replacing_language`, moves the slot to `wanted` (filtered on `available`), and the next grab — `GrabBookRelease` reads the flag — sets the record's `replace_mode = all`, so the importer removes the old file only after the new one is placed and clears the flag in `RecordBookImportSuccess`. A corrected `kind` (a heuristic, `metadata.ClassifyBookKind`) survives a refresh: it is written only when a stub is hydrated.

**Hardcover is called in batches of twenty.** Depth limit 3, 60 req/min through the 1 req/s limiter, 5,000 req/day (`hardcoverDailyBudget`, a UTC-day counter of requests actually sent) with `hardcoverScanReserve` (500) left to adds, refreshes and approvals: the bulk-import scanner and every background pass (`budgetLow`) stop at `Remaining() <= ScanReserve()`. The batch query (`GetBooks`, `hardcover_books.go`) reads up to 20 books with three aliased edition lists in one request; `cached_contributors` carries the makers and a book whose blob names none is read through the `contributions` join (one more request, only for those). A batch Hardcover cuts off is halved and retried (each retry spends budget). Costs: lookup 2 requests (1 with `type`), memoised 5 min per normalised query; lookup detail 1 (book) or 2 (series: skeleton + one batch of the first six volumes), memoised 10 min; add book 1; **add series `1 + ceil(N/20)`, of which two are on the HTTP request**; refresh book 1; refresh series `1 + ceil(N/20)`; scheduled refresh `ceil(B/20)` per ≤ 100 stale books plus a series pass for ≤ 5 stale series. A `429` or an exhausted day is `*metadata.RateLimitedError` wrapping `metadata.ErrRateLimited` and never sets `hardcover_auth_warn`; add, refresh, lookup and approve answer `429` `code: rate_limited` with `Retry-After`, no key answers `503`, and `RefreshStale` stops its tick at the first one and returns nil. `streamline.metadata.hardcover.requests{outcome}` counts it.

**Series add is two-phase.** Phase one (synchronous, the 2 requests): the skeleton (`series` + numbered `book_series`, one request) and the first 20 volumes; one transaction writes the series, those volumes fully hydrated and a **stub** `Book` for every other position (`last_refreshed_at NULL`, placeholder title `"{Series} #{n}"`, no editions, slot flags from the series policy). The series answers `hydrating: true`. Phase two: one process-wide worker (`HydrateSeriesInBackground`, `defer RecoverPanic`, span `book.hydrate_series`) drains stubs in batches of 20, each volume in its own settle step (series policy against the series' creation time, the series' chosen `(language, publisher)` edition); a stub Hardcover no longer knows, or that is a compilation, is deleted when it holds no file. **A stub is never searched, grabbed or imported** (the importer holds the record; `GrabBookRelease` answers `ErrNotHydrated`), and restart recovery is free: `RefreshStale` hydrates stubs *first*. A volume already in the library as a standalone book is **adopted** into the series (its data kept); one in another series is skipped and logged. Series `monitor` (`all`/`future`/`none`, stored) applies to each volume's **ebook** slot only; `future` is measured against the moment of the patch (or `BookSeries.create_time` for volumes a refresh finds). `BookSeries.quality_profile` is written through to every volume, and resolution for a book is `Book.quality_profile` → its series' → **the default for the book's kind** (`book_quality_default_profiles: {novel, bd, comic, manga}`, `config.ResolveBookQualityProfile(name, kind)`, `book.ProfileFor`). `PATCH series edition` takes a label from `BookSeries.editions` (`"{language in its own name} · {publisher}"`, ordered by volumes covered) and re-picks only the volumes **without** an ebook file; volumes with one keep file and edition.

Metadata is Hardcover (GraphQL, `metadata.hardcover_api_key` or `_file`): **the key is optional** — without it `wire.go` leaves the provider nil, the service answers `ErrNotConfigured`, the handlers answer `503` and the add page says Hardcover is not configured. Every Hardcover-dependent handler (search, lookup, add, refresh, request approve, import start and commit) builds that 503 through `errHardcoverUnavailable` (`restapi/hardcover_errors.go`): `code: hardcover_not_configured` for a missing key, `code: hardcover_key_rejected` when Hardcover answered 401 (the import operations can only report the first; a key rejected mid-scan surfaces after the fact). The key is settable through `PATCH /config/metadata` like TMDB/TVDB, restart required. `library.book_language` (ISO 639-1, runtime-editable, default `en`) seeds `Book.preferred_language`; `library.book_series_naming` (file-only; **not** `library.series_naming`, which is the TV template) names an ebook volume of a series (`{Author}/{Series}/{Series} - Vol. {Volume:02}`), `ebook_naming`/`audiobook_naming` gain `{Language}`, `{Series}`, `{Volume}`, and `{Title}` is the slot edition's title. Covers and creator photos come through the posters proxy under the `books` and `authors` kinds, fetched in the background from the CDN address the Hardcover payload already carried (never a Hardcover request); lookup art is `artwork.Remember(KindBooks, id, Source{URL})` as lookup and detail responses are served.

**The shelf** (`GET /books`, `internal/db/book_shelf.go`) is one raw-SQL `UNION ALL` of standalone books and series — ent cannot union, and merging two paged ent queries gives wrong deep pages — with the filters applied inside both arms and the derived status filtered, ordered and paged outside; counts are faceted (each facet counted with the others applied and its own left out, each with an `*_total` row, authors keyed by folded creator name so homonyms merge). Live download progress comes from `download.Queue` matched to the book's active records (`ListActiveBookRecords`); the download manager is untouched.

**Acquisition**: `ParseBookRelease` (bare `MP3`, `M4A` and `FLAC` without audiobook context are music, never a book; `CBR` is a comic container only when the name carries no audio token and no `CBR 64`-style rate; a stated audiobook rate lands in `BitrateKbps`; `Language` from the design's word list, `Volume`/`VolumePrefix` from `tome|volume|vol|t|v|#` + digits, fractional allowed; ranges and `intégrale` are collections) with `ScoreEbookRelease`/`ScoreAudiobookRelease` (and `Judge*` for the reject reason), `indexer.Manager.SearchBook` (7000+7020 ebook, 3030 audiobook; the query is `author + slot edition title (+ year)`, never an alias list). `POST /books/{id}/search` returns **flat** `SearchResult` items (`slot`, upper-case container in `source`, `bitrate_kbps`), both slots merged without `kind`; the grab reads the slot from the release's parsed container and refuses a body whose `slot` disagrees (`grab_rejected`), `kind` and the body slot disagreeing is a `400`. **Automatic paths only** skip a release tagged with a language other than the slot edition's (`book.WrongLanguage`); interactive search never filters on language. `SearchMissing` walks standalone slots one by one and groups series volumes: `searchSeriesVolumes` runs **one** query per series, takes each volume's best accepted match by parsed `Volume`, and makes at most 3 per-volume fallback queries; `search-now` for a book or series runs the same pass in the background and answers `202 {queued}`. Both the music and book services export `ErrNoQualityProfile` (`422`, `code: no_quality_profile`).

**Import**: the book importer places one best-format file for an ebook and the whole folder, original filenames kept, for an audiobook (`library.BookDestination`), and a failed audiobook import removes what it placed. A record is **held** (`Check: metadata`) when the book is an unhydrated stub or has no `author_name` — never a wrong path. A volume import flips both the `book` and the `book_series` request. **Rename** (`POST /books/{id}/rename`, `/books/series/{id}/rename`) moves an ebook to its template path and an audiobook folder whole, never onto an existing file.

**Adoption** is `ImportScan.kind=book`: ebooks group by `(dir, stem)`, every folder directly holding audio is one audiobook candidate, identification runs Calibre `metadata.opf` → embedded epub OPF → filename, then `BookByISBN` short-circuits `SearchBooks`; the scanner spends 1 search (+1 ISBN lookup) per candidate and **no** book fetch. The committer prefetches its reviewed books in batches of 20 (`ceil(C/20)` requests) and adds an unknown book **unmonitored** through `AddBook`; nothing is ever written into a book file. Both `StartScan` and `Commit` refuse `kind=book` without a Hardcover key (`book.ErrNotConfigured`, 503). **OPDS** is `internal/server/opds` at `/opds` (OPDS 1.2 Atom: root, `/authors` — authors and writers of a book holding an ebook —, `/authors/{id}` with volumes included, `/recent`, `/search.xml` + `/search` over title or any contributing author, `/download/{bookID}/{format}`), HTTP Basic against `User.opds_token`, **ebooks only**, `<author>` is every maker, one acquisition link per book at the best profile format. Cover links point at `/posters/*`, which stays behind the session middleware, so Basic-auth readers get no thumbnails. **Automation**: `rss/book_feed.go` gates 7000–7999 to the ebook matcher and 3030 to the audiobook matcher; a release matches a standalone book by `Author - Title` against any of its title forms (display, original, every edition title) and a series volume by the series name plus the parsed volume number, the author optional. **Requests**: `media_type` `book` and `book_series` carry a Hardcover id (two id spaces, hence `media_type` in the dedup key); approving a book adds it `both`, a series `all`, under the reviewer's profile (empty means the family default, a name outside the family answers `422` and the request stays pending).

## API conventions
- Every list endpoint bounds `limit` to `[1, 100]` (200 for activity) and **400s** a value outside it (`pagination.go` `limitOr` — there is no request-validation middleware, so the spec's bounds are enforced there). The SPA's `apiAllPages` (`web/app/lib/api.ts`) walks pages at `PAGE_LIMIT = 100` against `total`; the handlers used to clamp silently, and asking for `limit=500` — which nine call sites did — showed 100 of 621 movies with no indication anything was missing.
- `otelx.RecordSpanError(span, nil)` returns nil and leaves the span alone. It used to deref the error for `SetStatus`, so a missing `if err != nil` was a panic the handler reported as a 500 nowhere near the mistake — which is exactly how `BulkDecide` shipped and how the dev server caught it.
- Connection-test 422s carry `code: connection_failed` and the SPA renders their message verbatim — it is composed by our own client code and is the only place the upstream status appears. A plain 422 reads "some of those values weren't accepted", which blames credentials that are fine.
- **A search result's `download_url` is a sealed handle, not the indexer's link** (`restapi/release_handle.go`): AES-GCM under a key derived from the session secret, prefixed `slr1.`, opened by `toIndexerResult` on the way back in. The link carries the indexer's API key and search is a member endpoint. A plain link in a grab body still passes, held to the indexer allowlist by `checkReleaseSource`; `info_url` goes out through `otelx.RedactURL`. Rotating the JWT secret retires every outstanding handle; a grab carrying one answers `grab_rejected` saying to search again, not the missing-field 422.
- **A refused grab answers `422` with `code: grab_rejected`**, and the SPA renders that message verbatim (`errorText`, same arm as `connection_failed`). All six grab handlers share it — `GrabMovieRelease`, `GrabEpisodeRelease`, `GrabSeasonRelease`, `GrabSeriesRelease`, `GrabMusicAlbumRelease`, `GrabBookRelease` — over `download.ErrUntrustedSource`, `ErrNoWantedFiles` (video only; album and book grabs take the whole torrent), `ErrClientFull` (the builtin engine at its `maxTorrents` constant) and `ErrUnsafeTorrentName` (a `.torrent` whose name the engine's path guard refuses). Without a code the SPA falls through `BY_CODE` to `byStatus(422)` and shows its generic "some of those values weren't accepted", which blames the request body: on the homelab, two anime episodes refused for `ErrNoWantedFiles` (the `SxxE<absolute>` keep-set gap) were indistinguishable from a malformed release payload, and the message naming the actual reason — the sentinel plus the caller's own release title — was discarded before it reached the screen. `errUnprocessable` still has no code by design; a 422 whose message is a *diagnostic* rather than field validation needs one, or the message never renders.
- **`replace_existing: true` on a music or book grab sets the record's `replace_mode = all`** (the field the importer already honours; the RSS upgrade arm sets `upgrades`). The old files go only **after** the new ones are placed and verified: per matched track for an album, per linked album that already had files for an artist pack, every file of the grabbed slot for a book (a replaced audiobook folder is removed whole, the other slot is never touched). A held or failed import leaves the originals. Accepted and a no-op on a title with no files.
- **A list response must be an inline `type: array` schema, not a `$ref`'d `components/responses` array.** oapi-codegen turns the `$ref` form into a struct embedding the slice, which encodes as `{"TypeName": [...]}` rather than a bare array — `/music/quality-profiles` and `/books/quality-profiles` shipped answering an object until the spec was inlined.
- **`GET /requests/{id}/metadata` for an artist, book or series calls the same handler method as its lookup detail** (`GetMusicArtistLookup`, `GetBookLookup`), so the request panel and the add flow share one cache and one provider budget; 429 and 503 pass through and the SPA falls back to the title without retrying.
- **A 422 for a title with no usable quality profile carries `code: no_quality_profile`** (`errNoQualityProfile`), for the same reason: the album and book-slot search/grab endpoints would otherwise fall to the SPA's generic 422 line.
- **A Hardcover `503` carries `code: hardcover_not_configured` or `code: hardcover_key_rejected`**, distinct from `rate_limited` (429). One helper builds it (`errHardcoverUnavailable`); a handler that returns the book provider's 503 with `errServiceUnavailable` leaves the SPA unable to tell a missing key from a refused one from an outage. Approving a book or series request answers the same codes (and `429`) and the request stays pending.

## Testing
- Framework: Ginkgo (Describe/Context/It/By) + Gomega assertions
- Mocks: Mockery (`go tool mockery`) — config in `.mockery.yaml`, generated to `internal/<pkg>/mocks/`
- Run tests: `task test:unit` / `task test:integration` / `task test:e2e` / `task test` / `task test:coverage` — all `go tool ginkgo run -r --keep-going`; the first three and `test:coverage` (`!e2e`) carry a label filter, `task test` runs everything unfiltered (e2e capped at `--timeout=1m15s`); forward extra args via `CLI_ARGS`, narrow with `LABEL_FILTER=`
- `task test:e2e:containers` — container-backed e2e (Docker + `STREAMLINE_E2E_CONTAINERS=1`, 5m timeout); hermetic `test:e2e` excludes `containers`-labeled specs.
- Run single suite: `task test:unit -- ./internal/metadata/...`
- Each Ginkgo suite has a dedicated `<pkg>_suite_test.go` (the three `internal/utils/*` packages inline it in their single test file) with `TestX` + `RunSpecs` + `BeforeSuite(func() { DeferCleanup(testutil.InstallSlog()) })` — `testutil.InstallSlog()` routes `slog.Default` to GinkgoWriter for the suite's lifetime.

- Regenerate mocks after interface changes: `go tool mockery`
- Span-instrumented funcs wrap ctx via `tracer.Start(...)`, breaking exact-ctx mock matchers. Use `mock.Anything` for the ctx param in `.EXPECT().Fn(mock.Anything, ...)` calls.

## Multi-agent fix workflows
Convention for landing a batch of independent fixes (audit findings, review comments, a bug list). Iterate on this as we learn.

- **Group findings by file ownership first.** Two agents editing one file is the failure mode; disjoint file domains are what make the rest safe. One group per domain (e.g. `restapi/`, `download+importer`, `middleware+web`, `auth+db+ent`).
- **One workflow per group, one agent per finding.** Each fix agent runs with `isolation: 'worktree'` so it can never see or clobber another's tree. Agents fix *only* their assigned finding — no drive-by refactors, no fixing things they notice.
- **Seed every worktree before the agents build.** A fresh worktree cannot compile *anything* importing `web`: all four `go:embed` inputs are gitignored — `web/static/css/style.css`, `web/static/css/docs.min.css`, `web/static/js/docs.min.js`, `web/static/dist/`. The failure reads `pattern static/css/docs.min.css: no matching files found`, which looks like broken code and is not. Copy them in from the main checkout right after launch (they stay gitignored, so they never pollute a patch); re-run the copy as assemble-phase worktrees appear. Building them per-worktree instead costs a full pnpm+esbuild+tailwind cycle per agent.
- **Agents commit; they do not emit patches.** Every fix agent ends by committing its work on its worktree's own branch, one commit per finding, with a real Conventional Commits subject. Integration is then a merge/cherry-pick against a shared ancestor — a proper 3-way merge that understands moved and adjacent hunks. Patch files were the earlier convention and they mangle exactly this: a flat diff has no base, so two agents editing neighbouring lines of one file produce hunks that apply cleanly in isolation and silently mis-stack when combined. Commits carry the base; diffs don't.
  - Inside a harness worktree the agent uses `git commit` (the worktree is a git worktree, not a jj workspace — this is the "raw git plumbing" exception, not a licence to use git elsewhere). The integrating session brings the work across with jj, which sees those commits after its automatic import.
  - If a patch file is ever unavoidable, generate it with `git diff --no-ext-diff`: this machine sets `diff.external = difft`, so a bare `git diff > x.patch` writes difftastic's *rendered* output — diff-shaped, no `---`/`+++`/`@@`, and `git apply` rejects it with "No valid patches in input". Applying is unaffected; only generation.
- **Agents never write to the main working copy.** A per-workflow assemble agent merges the group's commits in its own worktree, resolves intra-group overlap, verifies `task build:go`, and leaves a single reviewable branch.
- **The main session integrates.** Workflows finish in any order; the session reviews each group's commits, brings them into the working copy, and verifies — serialized, so nothing races on the tree. Never let a workflow write to main itself.
- **Codegen runs once, at the end, in the main tree.** `task generate` / `task migrate:diff` rewrite `ent/*` and `internal/*/mocks/*`; per-workflow codegen produces conflicting generated files against a partial tree. Agents may run it inside their worktree to compile-check, but must keep generated output out of the commits they hand over. Migrations from `task migrate:diff` *are* handed over, unedited.
- **Verification is the session's, after integration** — `task build:go`, `task lint:go`, `task test:unit` over the merged result. A group that passed alone can still break the merge.
- **Clean up after integration.** Remove each group's worktrees and their `worktree-*` branches once its work is in and verified. They live under `.claude/worktrees/` *inside* the repo, so until they go the editor/LSP indexes every half-finished agent tree and reports its errors as if they were yours.
- Agents get no history rewriting and no publishing: no `jj`, no rebase/amend of anything they did not create, no push, no `task dev`, no `task release:*`.

## Nix
- `nix/` holds the whole surface: `package.nix` (buildGoModule over a `frontend` derivation that runs the same pnpm/esbuild/tailwind pipeline as `build:js`+`build:css`), `go.nix` + `node.nix` (the toolchain pins), `options.nix` + `common.nix` (shared by both modules), `module.nix` (NixOS), `hm-module.nix` (home-manager), `test.nix` (two-node VM test). Flake outputs: `packages.streamline`, `overlays.default`, `nixosModules.streamline`, `homeModules.streamline`, `checks.{build,nixos,home-manager,lint}`.
- **Two hashes, a version and two base-image digests are derived, not written.** `pnpmDeps.hash` moves with `pnpm-lock.yaml`, `vendorHash` with `go.sum`, `version ? "X.Y.Z"` is rewritten by `release:app:changelog` (`app:tag` refuses a mismatch), and `deploy/Dockerfile`'s `GO_DIGEST` and node digest follow tags nothing else rewrites. `.github/workflows/renovate-pins.yaml` derives all but the version, on renovate's own branches. CI's `nix` job filters on exactly those inputs, so a lock change is what triggers the expensive check.
- **`flake.lock`'s nixpkgs decides both toolchain versions; nothing else gets a vote.** `nix/{go,node}.nix` pick a nixpkgs package and never build one — `go.nix` takes `go_1_NN` from go.mod's `go` directive, `node.nix` takes `nodejs_NN` from `package.json`'s `engines.node` (stripping the `>=`) — then **throw unless the package's version equals the declaration exactly**. A devshell a patch away from what CI builds with is not a reproduction of it, so the drift fails at eval with both numbers named rather than later as `ERR_PNPM_UNSUPPORTED_ENGINE` or an opaque Go toolchain error. Only the patch is ever synced; the minor and the major stay where the declarations put them, so moving to a new Go minor or Node major is a human edit.
- **The declarations are generated from the lock, in that direction.** Renovate's `nix` manager bumps the `nixpkgs` input; `renovate-pins.yaml` then reads `go_1_NN.version`/`nodejs_NN.version` back out of the *locked* nixpkgs and rewrites go.mod, `engines.node`, `deploy/Dockerfile` and the six workflow `node-version`s on that branch. The built-in gomod/npm/dockerfile managers are `enabled: false` for those deps — left on they would offer upstream's newest release, which is the one version nix cannot use, and the equality throw would make it a permanently red PR. `engines.node` is a **`>=` floor**, for anyone building without the devshell; pnpm enforces a project's own `engines` unconditionally, so an exact value there breaks `pnpm install` for everyone not on that patch.
- **`GOTOOLCHAIN = "local"` is set twice, deliberately.** `buildGoModule` sets it for `nix build` (`pkgs/build-support/go/module.nix`), and `flake.nix`'s devshell env sets it again because nothing else does for `nix develop` — the default, `auto`, silently downloads whatever toolchain go.mod asks for, which would paper over exactly the mismatch `nix/go.nix` exists to refuse, in the one shell meant to be the reproduction.
- The package `src` is a fileset that **excludes** every frontend build output (`web/static/dist`, `style.css`, `docs.min.*`, `.routify`, `lib/paraglide`) — they are gitignored, so leaving them in would make the source hash depend on whether someone ran `task build:js` locally. `.golangci.yml` rides along for the `lint` check only; `e2e/` is deliberately out, since its rod deps are not in the vendored module set.
- **The config file is runtime-writable, so the module picks a side.** `mutableSettings = true` (default) seeds `settings` into `${stateDir}/config.yaml` on first start and never touches it again — the UI works, and a rebuild does *not* re-sync. `false` serves the store file and forces `read_only`, which is the only way a store path is safe: without it `config.Update` fails on a read-only filesystem instead of returning `ErrReadOnly`.
- `ffmpeg.path` is a **directory** (`resolveBinary(dir, "ffprobe")`), not the executable. `hardwareAcceleration.enable` only opens `/dev/dri` — `ffmpeg-headless` still cannot use it, and `ffmpeg-full` is the build carrying VAAPI *and* libvmaf (without which `transcoding.verify.min_vmaf` parses and silently never runs).
- `ProtectSystem = "strict"` means `ReadWritePaths` is load-bearing: it is the union of `stateDir`, the absolute `data_dir`/`movie_path`/`series_path`/`download_path` derived from `settings`, and `extraReadWritePaths` — which **adds** rather than replaces, because a computed `default` on a plain list option would silently drop the derived paths the moment a user set it. A library root added only through the UI is never granted. A path that does not exist yet fails the unit with a mount-namespace error, not a streamline error.
- The `lint` check is `packages.streamline.overrideAttrs` running `go tool golangci-lint`, not a standalone `runCommand` — golangci-lint type-checks, so it needs the module cache and the `//go:embed` assets buildGoModule already arranges. The old standalone check had neither and only ever reported "could not import entgo.io/ent" from a network-less sandbox.
- User-facing docs: `docs/wiki/NixOS.md` (linked from `Installation.md` and `_Sidebar.md`). Format with `task fmt` (nixfmt over `flake.nix nix/*.nix`); `nix fmt` also works via `formatter`.

## Docs & Spec Upkeep
- Any change to `/api/v1` behavior — routes, auth/authz, status codes, security schemes, request/response shapes — updates `api/openapi.yaml` in the same change, then `task generate` to regenerate `gen.go` (the spec itself is served from `api/embed.go`'s `//go:embed openapi.yaml`). A handler and its spec entry must never disagree.
- When a feature or behavior changes, update the affected CLAUDE.md section — **or the `docs/agents/` file its stub points at, when the change lands in one of those subsystems** — **and the wiki** (`docs/wiki/` — user-facing pages like `REST-API.md`, `Authentication-and-SSO.md`) in the same change — stale docs describing the old behavior are worse than none.
- `docs/agents/` holds the subsystem detail this file used to carry verbatim — nine files, one per area, each behind a `##` stub above. `docs/agents/README.md` is the index and states the upkeep rule. A stub and its file must never disagree: the stub carries the shape and the load-bearing invariants, the file carries the rules and the reasons.
- `docs/wiki/` is the source of truth for the GitHub wiki; `.github/workflows/wiki.yaml` mirrors it to `DataHearth/streamline.wiki.git` on every push to `main` touching it. Filename = page title (dashes become spaces), `_Sidebar.md` is the nav. Never edit through the wiki UI — the next sync overwrites it.

## Code Generation
- API: `go tool oapi-codegen --config api/oapi-codegen.yaml api/openapi.yaml` → `internal/server/restapi/gen.go` (package `restapi`) — regenerate after spec changes
- ORM: `go generate ./ent` — regenerate after schema changes
- All codegen: `task generate` (runs `go tool oapi-codegen`, `go generate ./ent`, `go tool mockery`). Versioned migrations: `task migrate:diff -- NAME` diffs the ent schema into a new migration.
- Prefer the narrowest integer type on ent schema fields (`field.Uint8` for bounded counters like `grab_failures`, `field.Uint16` for small ranges like `number`/`year`) — sqlite storage is identical but Go structs stay memory-efficient.
- After ent regen the LSP may report "undefined" for new fields/methods briefly; `task build:go` is the source of truth.

## Build
- Task runner: [Taskfile.yaml](Taskfile.yaml) — sole build orchestrator (no npm scripts).
- **Always** invoke operations via `task <target>`. Raw `go build`/`go test`/`ginkgo`/`golangci-lint`/`pnpm exec` bypass the Taskfile and drift from CI.
- Go tooling runs via the Go `tool` directive: `go tool {ginkgo,golangci-lint,oapi-codegen,mockery,air,govulncheck}` (`task vulncheck` runs the last, as CI does) — not system-installed; the flake devshell only ships `go`, `pnpm`, `go-task`, `biome`, etc.
- **A tool-directive module needs its full `h1:` in go.sum, and only the tool jobs notice when it doesn't.** `build`/`test`/`lint-go` never build those packages, so a `go.sum` carrying just the `/go.mod` hash resolves fine for them and fails in `vulncheck` (`go tool govulncheck`) and in `nix`, where the `streamline-lint` goModules derivation runs `go mod download` over the whole set — as a builder error inside a fixed-output derivation, which reads like broken code. `renovate.json` sets `postUpdateOptions: ["gomodTidy"]` so renovate can't open a PR in that state; a hand-edited go.mod needs `go mod tidy`, not `go get` alone.
- Full build: `task` (= `build:app` → `build:go`, which depends on `build:js` + `build:css` because assets are `//go:embed`-ed) → `go build -o streamline ./cmd`.
- Frontend: `task build:js` (Scalar docs bundle + Paraglide message compile + `routify build` + esbuild SPA) and `task build:css` (TailwindCSS v4).
- Dev server: `task dev` — live reload via `go tool air` (`.air.toml`; rebuilds with `task build:app`, runs `streamline --config ./tmp/config.yaml`).
- Lint: `task lint` (`lint:go` golangci-lint + `lint:frontend` biome + `lint:ts` svelte-check). Format: `task fmt` (`golangci-lint fmt` + `biome format --write`) — Biome, not prettier.
- Clean: `task clean`.

## Release
- App and chart version independently, but they release the same way, so both live in one `release` namespace (`.taskfiles/release.yaml`). App: `task release:app VERSION=X.Y.Z`, which is `release:app:changelog` (regenerates the CHANGELOG **and rewrites `version ? "X.Y.Z"` in `nix/package.nix`** — `nix build` has no tag to read, so a nix install would otherwise report the previous release forever; `app:tag` refuses to tag until both are on main — commits them on their own revision and advances `main`) then `release:app:tag` (tags `main`, push fans out to `.github/workflows/{release,image}.yaml`). Chart: `task release:chart VERSION=X.Y.Z`, which is `release:chart:bump` (rewrites `version` in `deploy/helm/streamline/Chart.yaml`, regenerates `deploy/helm/streamline/CHANGELOG.md`, commits both, advances `main`) then `release:chart:tag` (tags `chart-vX.Y.Z`, triggers `.github/workflows/chart.yaml`); run the two apart to review the bump commit before the tag goes out. Bump the chart against the diff, not against the version already there — a renovate deps PR bumps the patch itself, so a feature landing after it inherits a patch number that claims nothing shipped. Both take `VERSION` as bare semver; a leading `v` is accepted and stripped, so the same string works for either. The tag prefix is the task's business — `v` for the app, `chart-v` for the chart. The shared halves are `release:_changelog` and `release:_tag`, internal and the only place the jj-vs-git commit dance and the tag push are written. `_tag` is all-jj since jj 0.45 (`jj tag set` + `jj git push --remote origin --tag`) — the tags it writes are lightweight, not annotated, which nothing here reads.
- Artifacts come from goreleaser (`.goreleaser.yaml`): CGO-free binaries for linux/darwin/windows × amd64/arm64, archives carry `config.example.yaml`, `checksums.txt` is cosign-signed (bundle format), one SPDX SBOM per archive. Images are cosign-signed keyless + SBOM-attested + grype-scanned in `image.yaml`.
- Both tags publish a GitHub release, and both bodies come from `.github/actions/release-notes` (composite): it extracts the version's CHANGELOG section, pipes it to the Claude CLI to rewrite as operator-facing notes (installed from `claude.ai/install.sh`, run from `RUNNER_TEMP` with the section on stdin and no tool granted — no file writes, no repo access), then appends the caller's install/verify footer. **Both workflows run it in a separate `notes` job** (`contents: read`, `persist-credentials: false`, workflow-level `permissions: {}`) and hand the file to the publishing job as an artifact: the installer is an unpinned `curl | bash`, and in the publishing job it ran beside the checkout's persisted token, cosign's OIDC token and the tree GoReleaser signs. `anthropics/claude-code-action` is deliberately *not* used: it rejects `push` outright (`Unsupported event type: push`) and both release lines are tag-push triggered, so the step never once ran under it. **The model is never load-bearing**: the step is `continue-on-error` and skipped entirely without `CLAUDE_CODE_OAUTH_TOKEN`, and empty output falls back to the raw changelog section — which is exactly what shipped before. A *missing* changelog section still fails the release, since that is our mistake and not the model's. The chart release is created with `--latest=false` so it does not displace the app release on the releases page.
- `release:app` / `release:app:tag` / `release:chart` / `release:chart:tag` / `release:image` / `release:helm` publish for real and have no dry-run. Both end-to-end targets commit *before* they reach the half that pushes, so a dry check must be `task --dry`, never a real run with a deliberately bad VERSION. Never run one to "test" it — only exercise a precondition's failure path.

## Version Control
- Repository uses jj (Jujutsu) with a git backend. Commit a task with `jj new -m "msg"` (creates empty child, auto-snapshots subsequent work). Seal a task by starting the next with `jj new -m "..."`.
- Don't re-run `jj describe` on a commit you're already working in — message is set once per task.
- If working copy holds unrelated leftover edits (e.g. settings.json), describe them into their own commit *before* `jj new` for feature work.
- Abandon empty working-copy commits after no-artifact steps (smoke tests, manual verification): `jj abandon @`.
- Commit messages: Conventional Commits `type(scope): msg` — add a `(scope)` where it clarifies, omit it when it doesn't. Bundle related changes; avoid single-file revisions.

## Project Structure

- `internal/` — all application code
- `ent/schema/` — ent ORM schemas
- `web/app/` — Svelte 5 SPA (`routes/`, `components/`, `lib/`); `web/static/` — CSS/JS/fonts/images; `web/embed.go` `//go:embed`s the built assets + SPA shell
- `docs/superpowers/{specs,plans}/` — design docs and plans (gitignored, local only; `docs/plans/` is the legacy location)
- `docs/wiki/Roadmap.md` — public, user-facing feature status (Shipped / In progress / Planned). Not an internal phase list; update it when a feature ships or starts.
- `CHANGELOG.md` — generated from conventional commits by git-cliff (`task release:app:changelog VERSION=X.Y.Z`); don't hand-write entries. Commits touching `deploy/helm/**` are excluded — those belong to `deploy/helm/streamline/CHANGELOG.md`, generated the same way but off `chart-v*` tags by `release:chart:bump` and packaged into the chart tarball. Two configs: `cliff.toml` (app) and `cliff.chart.toml` (chart). They exist separately only because `commit_parsers` differs and git-cliff exposes that neither as a flag nor as an env override — the chart promotes `chore(helm)` and `chore(deps)` into Changed, since a chart release is often nothing but those and cliff.toml's blanket chore skip produced a heading with nothing under it. The `chore(helm): chart vX.Y.Z` bump commit is skipped there, or it lands as an entry inside its own section. The templates are duplicated between the two files — keep them in sync. Path scope stays at each call site (`--exclude-path` for the app, `--include-path` for the chart), so a commit touching app *and* chart appears in both.
- `deploy/` — Dockerfile + Helm charts + `compose.yaml` (local test stack: gluetun VPN + qBittorrent + Prowlarr + Plex, builds from source — *not* a user deployment template)
- `deploy/helm/streamline/` — streamline chart (installs to `streamline` ns). Optional subchart `charts/observability/` installs upstream alloy/VM/VL/VT/grafana into `observability` ns via `namespaceOverride`.
- `deploy/helm/streamline/kubeconfig.yaml` — kind cluster kubeconfig (auto-exported by `task helm:kind:up`; flake devshell sets `KUBECONFIG` to this path).
- `nix/` — package, NixOS + home-manager modules, VM test (see **Nix** above)

## Helm Gotchas
- VM/VL/VT charts: at v0.35/0.12/0.0.7 the selector used `app: server` but the template labels dropped it, so `server.podLabels.app: server` is set in each subchart's values. The charts pinned in `charts/observability/Chart.yaml` derive pod labels from the selector labels, so the workaround is likely removable — verify against a rendered template before dropping it.
- Cross-namespace k8s DNS requires FQDN: `<svc>.<ns>.svc.cluster.local`. Streamline→alloy uses `alloy.observability.svc.cluster.local:4318`.
- OTel SDK defaults to HTTPS. The chart renders `otel.insecure: true` into the config for the subchart's Alloy (plain HTTP), and for any `config.otel.endpoint` written as `http://…` — it strips the scheme, since the exporters take `host:port` via `WithEndpoint`.
- The Grafana dashboard is rendered by the **parent** chart (`templates/grafana-dashboard.yaml`) for both the subchart's Grafana and `grafanaDashboard.enabled` (an existing Grafana's sidecar) — a subchart can't read its parent's files. `task helm:prep` copies `deploy/grafana/dashboards/streamline.json` into `deploy/helm/streamline/dashboards/` (gitignored). Panels use `$datasource`/`$logs` variables, never a datasource uid; the logs panel's plugin type and query are picked at render time (`grafanaDashboard.logs.type`), since a datasource variable is bound to one plugin type.
