# Frontend (Svelte 5 SPA)

> **Read before touching** `web/app/**`, `web/static/**`, `routify.config.js`, or `web/embed.go`.
>
> **Covers** — routing and layout conventions, data/forms/toast/icon stack, the two settings save models, server-side pagination and the facets that were dropped for it, accent-folded search, bulk actions, the PWA surface, and the bundling pipeline.
>
> **Not here** — REST shapes the SPA consumes (`../../CLAUDE.md` → API conventions), quality/profile UI semantics (`quality-scoring.md`).

## Frontend
- Svelte 5 SPA in `web/app/` (TypeScript everywhere — `<script lang="ts">`, `.ts` lib files). Entry `web/app/main.ts` + `App.svelte`; shell `web/app/index.html` (embedded as `web.SPAShell`).
- Routing: Routify v3 (`routify.config.js`) scans `web/app/routes/` → generated `web/app/.routify/` (gitignored, never hand-edit). A section's wrapping layout MUST be `_module.svelte` — a `_layout.svelte` renders as a sibling route, not a wrapper.
- Data/forms: `@tanstack/svelte-query` (`lib/query.ts`, `lib/api.ts`), `@tanstack/svelte-form`, `valibot` schemas (`lib/schemas.ts`). Toasts: `svelte-sonner` (`lib/toast.ts`). Icons: `@lucide/svelte`. Class merge: `lib/cn.ts` (clsx + tailwind-merge) — never duplicate elements in `{#if}/{:else}` just to swap classes.
- **The top bar never carries a page title; every section draws its own `h1` in the page.** `TopBar.svelte` returns no crumbs for a section root, so the bar shows breadcrumbs on detail pages and nothing else, in one fixed 22px row the header centres — the bar keeps its height whether a breadcrumb is there or not. A title in the bar on some tabs and an in-page `h1` on others put the heading in two different places between tabs (#73). The library lists (Movies, Series, Music, Books) put their count line under the `h1` (`text-2xl font-bold tracking-tight`); on Movies and Series it is `md:hidden`, since from md the row under the toolbar carries the same counts. A new section must render its own heading or it has none.
- **Manual search reads in plain words by default** (`components/shared/ReleasesTable.svelte`, facts in `lib/release-facts.ts`); the table is the « Technical details » switch, remembered per browser as `streamline:releases:technical`. Release language is parsed client-side from the name (MULTi/DUAL, VOSTFR, VF/FRENCH…, else VO) because the search API does not carry it yet — it belongs in the backend parser eventually, and then `langOf` reads that field. A file already on disk is described from its probe, never its renamed filename. Grabbing over existing files is a confirmation on **Select** (`existing` / `existingCount` props), not a toggle: a confirmed grab is what sends `replace_existing`. With `missingCount` above zero as well (the music modal passes an album's missing tracks, or for the discography those of the albums a pack would link — monitored, hydrated, not upcoming, wanted/paused/failed, `ListPackAlbums`' rule; `SeriesReleaseSearchModal` takes `missingCounts` per scope from the series page, counted as the server's `wantedAiredEpisodes` — wanted and not dated in the future — so the number is what a grab without replace is actually for) the confirmation gains a third, decisive answer, *Download missing tracks only*, which grabs **without** `replace_existing` — the importer already leaves a track holding a file alone in that case. `filesPath` (an album, a discography, a season or the whole show; not an episode) adds a *Files* toggle per release, one open at a time, and the same panel inside the confirmation: `components/shared/ReleaseFilesPanel.svelte` POSTs the release to `/music/albums/{id}/release-files`, `/music/artists/{id}/release-files` or `/series/{id}[/seasons/{n}]/release-files` and folds the answers into a flat list or, for a discography (`filesKind="discography"`), the waiting albums the pack fills — sorted filled first — plus the folders the import skips (`kind` tracks, episodes or discography; "missing" is a track with no file, or an episode the server marks `wanted`, i.e. wanted and aired) lazily, `retry: false` and no focus refetch, since every call is a `.torrent` fetch from the indexer. Never fetch it for the whole result list. `indexer_private` and `previously_grabbed_at` are stamped server-side on every search result (`quality-scoring.md` has the `ConfiguredIndexer` lookup).
- **Torrents, transcoding and imports are top-level routes** (`/torrents`, `/transcoding`, `/imports`), not `/activity/*` and `/library/*`. The Activity nav group therefore cannot rely on a recursive `isActive("/activity")` for its highlight — `activityGroupActive` (`lib/activity-nav.ts`) names all three routes. `[...404].svelte` `location.replace`s the old URLs before rendering, for bookmarks and an installed app's history. The API paths (`/api/v1/library/imports`, `/api/v1/torrents`) did not move.
- **Torrents and Transcoding are in the nav only while their feature is on** (`activityFeatures()` in `lib/activity-nav.ts`, read by `Sidebar`, `SidebarRail`, `BottomNav` and the search pages in `lib/search-model.svelte.ts`). Torrents needs an enabled `builtin` download client (the page lists that engine only, and `/torrents` 404s without one); Transcoding needs `transcoding.enabled` (`/transcoding/*` 409s while off). Both read the settings pages' own query keys (`["download-clients"]`, `["config","transcoding"]`), so a toggle there updates the nav at once, and both count as off until the config has answered, so a disabled row never flashes in at load. `transcodeCountsQuery` is gated on the same flag and no longer sends the nav's `/transcoding/queue` request to collect a 409. The routes themselves stay reachable by URL and still explain the off state; the Transcoding *settings* section stays in search, since that is where it is switched on.
- **In-flight work is visible app-wide from one component.** `components/layout/GlobalActivityBar.svelte` sits in `App.svelte` inside the `QueryClientProvider` and shows a 2px indeterminate bar whenever `useIsFetching() + useIsMutating() > 0`, after a 300ms delay so cache hits don't flash. Queries carrying `meta.silent` (sidebar badges, the dashboard's background polls) are excluded from the fetching count so a poll never raises the bar. It is `z-[300]` — above the modal layer (`z-50`) and the `Select` portal (`z-[200]`) — because the case that made it necessary was an indexer search taking ~15s *inside* a modal, which read as a stall. Per-view skeletons stay; this covers everything they don't, including background refetches that leave stale data on screen.
- **Every remote image goes through `components/shared/Img.svelte`, which reveals it only once it has decoded.** The `<img>` renders `opacity-0` and drops that class after `load` resolves `img.decode()`, so a slow connection shows the container background and then the finished image instead of painting it in bands (#62). Three ordering rules carry the whole design: the `transition-opacity duration-200 motion-reduce:transition-none` classes come **first** so a caller that animates the element keeps its own timing (`MovieDetailSimilar`'s `transition duration-300` hover zoom would otherwise be rewritten to opacity-only by tailwind-merge); `opacity-0` comes **last** so it beats a caller's own opacity; and the reveal *removes* `opacity-0` rather than adding `opacity-100`, so the blurred hero backdrops settle back to their `opacity-70` instead of being forced opaque. A `decode()` rejection calls the caller's `onerror` — guarded on the element still holding the src that was decoding, since `decode()` also rejects when `src` changes under it — and reveals anyway, so a caller without an error path gets the browser's broken-image behavior rather than an element hidden forever. `Poster.svelte` keeps only the 404 retry loop and passes `handleError` down; its `visible` flip remounts `Img` per attempt, which is what resets the reveal state. The four brand/logo `<img>`s (`AuthCard`, `BrandLogo`, `Sidebar`, `SidebarRail`) stay raw — local assets that never stream, and `BrandLogo` owns its own fallback. No skeleton and no BlurHash: the fixed aspect-ratio container every caller provides is the placeholder.
- **`GET /movies` filters, sorts and pages in SQL, and carries a `file_summary` rollup instead of `media_files`.** `movie.FilterList` + `db.FilterMovies` had existed as dead code since the series push-down; the handler still called the unfiltered `List` and the SPA pulled the whole library to filter in the browser. The rollup (`db.MovieFileSummaries`, one lean scan over the page's ids — the same trade `EpisodeCounts` makes for series) carries `file_count`, `size_bytes` and the *largest* file's parsed `resolution`/`codec`, which is everything the grid's size and quality columns, `MovieActionsMenu`'s file count and the bulk-action totals need. `media_files` is now **detail-only**; `MovieActionsMenu` reads `file_summary?.file_count ?? media_files?.length` because it opens from both. `db.ListMovies` and `movie.Service.List` are gone — nothing called them once the handler moved.
- **Cast is not a column on a title.** It lives in `persons` + `credits` and is read only by the two detail handlers, through `db.TitleCast`, in the credit's billing `order`. The list paths carry no cast at all, which is why they need no projection to avoid one: `movieListColumns`/`tvShowListColumns`/`withLeanMovie` existed solely to subtract the old `cast` JSON blob — ent decoded it into a `[]CastMember` per scanned row, and one page walk of a 610-movie library put 480 MB of garbage on that single `Unmarshal` for a field no list response emits — and died with the column. **The lesson survives them**: a JSON field on `Movie`/`TVShow` is decoded on every row of every list and drift sweep, so a new one needs that cost measured before it lands. `overview` was measured too and deliberately kept — a plain string column has no decode cost, and it *is* emitted.
- **Both library lists paginate server-side with an appending infinite query** (`routes/{movies,series}/index.svelte`), replacing `apiAllPages` + `IncrementalList`. The typed filter is debounced 250 ms before it reaches the query key, and both queries carry `placeholderData: keepPreviousData` — a new key otherwise falls back to `isLoading`, which unmounts the toolbar the user is typing in and takes the caret with it, so every keystroke read as a page reload. Consequences, all deliberate: the **tri-state monitored filter is gone** (`MonitorFilterTabs`, `MonitorFilter`, `?monitored=`), as is the movies footer's "N GB monitored" — neither survives paging without a `monitored` query param and a wider counts endpoint, and both were dropped rather than rebuilt. Tab counts come from `/movies/counts` and `/series/counts`; the latter grew `upcoming` and `missing` for exactly this, and `missing` reuses `db.missingEpisode` so the tab's count and the tab's contents cannot drift. Bulk selection and the "N of M" line now mean "of what has been loaded", not "of the whole library". The dashboard still walks all pages — its own problem, unmeasured, left alone.
- **`?query=` matches accent-folded, in SQLite, through a registered `fold()` function** (`internal/db/fold.go`, used by `FilterMovies` and `FilterTVShows` over title *and* original_title). `LIKE` folds ASCII case only, so `detective` matched none of `Détective Conan` — a French library was unsearchable without typing the accents. A Go callback per row costs nothing extra: a leading-wildcard `LIKE` scans the column either way, so no normalized column and no backfill. It mirrors the SPA's `fold()` (`lib/text.ts`), which is now the only client-side matcher left — the three search surfaces (`lib/search-model.svelte.ts`) query `/movies`, `/series`, `/episodes`, `/music/artists`, `/music/albums`, `/books` and `/people` with `query=` instead of pulling the libraries through `apiAllPages` and filtering `title` in the browser; pages and actions are still folded locally, and the "N of M" hint means matched, not library size. `model.pending` is true from the keystroke until every one of those searches has answered for the typed text (the 200ms debounce, then any `isFetching`): the field's search icon becomes a spinner and an empty list reads "Searching…", since "No matches" shown before the server was asked read as a verdict. An album and an episode have no page of their own: an album hit opens `/music/{artist}?release={album}` (the discography tab on that release), an episode hit `/series/{id}?tab=episodes&season=N&episode=ID`, which `routes/series/[id].svelte` reads off the route **params** (`window.location` still names the outgoing page at mount, so its `?tab=` writer only writes once the location is the series' own) and answers with one route-level `EpisodeDetailModal` — the phone accordion and the md+ table are both mounted, so opening the sheet inside each showed two; closing it strips `season`/`episode`. An artist matches on an album title too: one found only through an album whose own row is listed is left out of the list and of the "N of M" total (`foldedArtists`), and otherwise says which album matched (`via “…”`); a book series says its volume count where a book says its year. For an admin, every settings section (`SETTINGS_SECTIONS` in `lib/settings-nav.svelte.ts`, the one table the sidebar, the touch index and the top bar also read) joins the pages as `Settings · <section>` once something is typed — listed on an empty palette they buried every other page.
- **A cast member is a route, not an outbound link.** `MovieDetailCast` links each member to `/people/{person_id}` (`routes/people/[id].svelte`), which renders the person's library credits as two `PosterCard` grids — the character goes in the card's `detail` slot. **`person_id` on the cast entry is the only key that works**: a series actor comes from TVDB with `tmdb_id: 0`, so a link built from the provider id sent every one of them to the same page. `LookupDetailPanel` passes `external` to keep the provider link there instead: its cast belongs to a title that is not in the library yet, so those entries carry no `person_id` at all, and the panel lives inside the add/request modal, which a route change tears down. The endpoint 404s a row id no person occupies, so the page treats a 404 as an empty state rather than a failure and sets `retry: false`. `lib/people.ts` holds the initials monogram both the grid and the page fall back to; `lib/status.ts` grew `seriesStatus` so the credits grid and `SeriesGrid` badge a show the same way. The three search surfaces also fetch `/people` on the same `titleSearch` gating as the two libraries, in a `people` section ordered under the title hits — people are deliberately **out** of `titleHits`/`searchable`, which describe the libraries.
- **The bulk bar's `⋯` covers the per-title kebab minus what the bar already promotes, and minus what has no bulk meaning.** `{Movie,Series}BulkActions` promote Monitor/Unmonitor/Search/Quality to buttons, so the kebab holds only Rename/Refresh/Delete. **Change match** is per-title by construction — it repoints one row at one provider id — and correctly has no bulk form; **Rename files…** was the one real gap, and it is the action a naming-template change needs across a whole library. It applies without a preview (one per selected title is a request each to render a list nobody reads at that length — the per-title kebab keeps its preview modal), behind a confirm, over the subset with files on disk (`file_summary.file_count` / `have_episodes`) so the toast's count is what was acted on. `run()` in both components takes that subset as an optional last argument; everything else still defaults to the whole selection.
- **Torrents and Activity (queue and history) carry bulk selection too, admin-only, and each action runs on the subset it applies to.** `TorrentBulkActions` and `DownloadBulkActions` reuse `BulkActionBar`/`BulkTouchBar` and `runBulk` (there are still no batch endpoints). Pause takes what can be paused (the drawer's own `canPause` set for a torrent; anything not paused for a record), Resume takes only paused rows, and a **held** record is left out of pause, resume and cancel alike — the server 409s all three on it, so counting it as a failure would read as a bug. The toast counts what was acted on, not the selection. Selection state is `lib/selection.svelte.ts` (`Selection<K>`, keyed by hash or record id so the 2 s poll cannot strand a stale row; pruned when a row leaves the list, cleared on any filter or view change). The tables grow a `SelectBox` column; below md there is no checkbox, so a press and hold on a `TouchRow` (`lib/long-press.ts`) starts selecting, every tap then toggles, and the top bar becomes the selection: `SelectionTopBar` draws nothing in place and claims `lib/selection-header.svelte.ts`, which `TopBar` renders below md as close · count · select all over its own row (made `invisible`, not unmounted, so the header keeps its height). This is the contextual app bar Gmail, Photos and iOS Mail use. It replaced a band pinned under the top bar, which pushed the list down as selecting began, hid the toolbar or chips it took the line of, and sat between the rounded cards as a strip belonging to neither; the toolbar and chips now stay on screen throughout, on Movies and Series too. The long press swallows the following click on the **window**, not the row: entering selection mode re-renders the row, so the element that saw the hold is not the one the click lands on.
- **The open torrent is in the URL (`/torrents?hash=<info hash>`), and a queue or history record links to it.** The Torrents page seeds `selectedHash` from `?hash=` and `replaceState`s it as the drawer opens and closes, so the drawer survives a reload and anything can deep-link it. **The seed reads Routify's `params` store (which merges the query string), not `window.location`**: on an in-app navigation the page mounts before the address bar holds the new URL, so a `window.location` read found `/activity` and the link landed on a closed drawer while a reload of the same URL worked; for the same reason the sync effect writes only while `location.pathname` is `/torrents`. a hash missing from a *settled* listing (`isSuccess && !isFetching`, so the nav's cached copy cannot drop a hash the refetch on arrival brings in) clears the selection, which also stops the detail query polling a 404 after a torrent is removed elsewhere. Queue and history entries carry `torrent_hash` (lower-cased server-side); `ExpandedRowDetail` and `ActivityDetailSheet` show **Open torrent** when `torrentHref` (`lib/activity-nav.ts`) finds it in the builtin engine's list — `builtinTorrentsQuery()`, the same `["activity","torrents"]` entry the nav counts already poll, so the Activity page adds an observer, not a request. The page shows that engine only, so a record held by qBittorrent, Transmission or Deluge, or whose torrent is gone, gets no link rather than a drawer that cannot open. The link shows on a held record too: its torrent is still there to inspect, and the verbs it hides are the record's.
- **The Activity and Torrents touch rows swipe: right for the row's start action, left for its end action** (`TouchRow`'s `swipeStart`/`swipeEnd`, gesture in `lib/swipe-row.ts`). Queue: pause or resume / cancel; history: retry import (failed only) / remove; torrents: pause or resume (the drawer's `canPause` set) / remove. Each list derives its swipes from the same rules its sheet uses for buttons, so a swipe never offers a verb the sheet hides; a held record has none, and none exist for a non-admin or while selecting. Pause and resume run at once, like the sheet's buttons; cancel, retry and remove open **the same dialog** the sheet or drawer opens (`DownloadConfirmDialog`, `TorrentRemoveDialog`, both extracted for this), so a swipe never destroys anything on its own. The row keeps `touch-action: pan-y`: a gesture becomes a swipe only once it has moved 10px and clearly sideways, a vertical start stays a scroll, and the move cancels the long press first. Letting go past a third of the row (capped at 112px) commits, the revealed action filling with its colour at that point; the lift's click is swallowed (`swallowNextClick`, shared with `long-press.ts`) so a swipe never also opens the sheet. The divider moves to a wrapper around a swipeable row, because `last:` has to see the list's own children.
- **The dashboard's "Recently added" and "Wanted" rows both mix movies and series, and sort on `added_at`** (`Movie.added_at`/`TVShow.added_at`, ent's `create_time`, added for exactly this). Neither row could order the two kinds before: both list endpoints default to `create_time DESC` *within their own kind*, which says nothing about how they interleave. "Recently added" carried no series at all, and "Wanted" built `[...movies, ...series].slice(0, 6)` — mapping series in, then always truncating them away whenever six wanted movies existed.
- **For a series, "Recently added" sorts on `last_added.at`, not `added_at`, and the card names the batch** (`additionLabel`). `added_at` is when the show record was created; a show followed since March that took an episode this morning is one of today's arrivals. The SPA half of this shipped first and read a field nothing sent, so the rail silently kept sorting shows on their add date — a new episode, season or show with old files never surfaced. The server half is `EpisodeCounts.LastAdded` (`media-lifecycle.md`).
- **Settings pages pick one of two save models, never both on a page.** Save-per-control with no form and no Save button (`series`, `media-probe`, `library`, `transcoding`): checkboxes and selects fire on change, text inputs commit on blur, and a `drafts` record keyed by field name is what stops a focus-refetch from overwriting what is being typed. Or a TanStack form with a valibot schema and one Save (`auth`, `metadata`, the resource modals), whose `$effect` re-seeds *only while the form is clean*. `settings/library.svelte` is per-control precisely because it straddles two endpoints (`/config/library` + `/config/download`) that one form could not submit together; `settings/metadata.svelte` is a form because its password fields want an explicit commit. A new page adds its route, a `SETTINGS_TITLES` entry and a `createSettingsNav` item — the sidebar and the touch index read the same list.
- **Every config page calls `markConfigForm()`, whichever save model it uses.** `readOnlyLock()` returns false outside that context, so the field primitives (`TextField`, `Select`, `FieldLock`) lock themselves only inside it. The form pages get it free from `ReadOnlyFieldset`; the six save-per-control pages (`advanced`, `general`, `library`, `media-probe`, `series`, `transcoding`) had nothing establishing it, so they hand-rolled `readonly={config.readOnly}` onto each raw `<input>` — and every `<Select>` on them stayed live on a read-only instance, opening a dropdown whose choice the server would reject. The call at the top of each page is the fix; the hand-rolled attributes are now redundant but harmless.
- **A keyboard hint names the platform's modifier.** `lib/platform.ts` exports `modKey`, "⌘" on Apple devices (macOS, iPhone, iPad) and "Ctrl" everywhere else; the top bar's search hint reads `{modKey} K`. It used to say "⌘ K" on every platform, a key Windows and Linux keyboards do not have. The handlers keep accepting both modifiers, so this only changes what is shown.
- **A `type="search"` input draws its own clear button; the native one is hidden globally.** `input.css` strips `::-webkit-search-cancel-button` in `@layer base`, because every search field also rendered a themed lucide `X` and Chrome Android paints the native cancel as a full-size white glyph beside it — two crosses doing one job (#72). The type stays for the phone keyboard's Search key. The flip side is that a new search field with no `{#if q}` clear button has no way to clear at all; three (the two import-scan filters and the users list) had relied on the native one and grew a button with the rule.
- **Every visible string is a Paraglide message, and a message is a whole sentence.** Gluing English around a value is what left French screens reading "Valider 3 files" and "636 titles · scan cette minute-ci": a noun with an `s` appended, or a translated first half followed by a hard-coded second half. Three helpers carry the rule. `lib/nouns.ts` holds a `Noun` per counted thing (`NOUN_TITLE`, `NOUN_SERIES`, `NOUN_FILE`, `NOUN_SHOW`, `NOUN_EPISODE`) with `count(n)` from an `_one`/`_other` pair and `items`, the whole set with its article ("titles" / "les titres"); `BulkActionBar`, `BulkTouchBar`, `SelectionTopBar`, `MediaFilterSheet` and the import `DecisionStrip` take a `Noun`, never a string, and the status tallies (`countWanted`, `countMissing`, …) live there too. `lib/message-parts.ts` keeps a sentence whole while one or more slots carry markup: `around()` for one highlighted word, `parts()` for several, returned in the translation's own slot order so a language may reorder them. `lib/roles.ts` `roleLabel()` is the only way a role is displayed. Counts pick `_one` vs `_other` on `count === 1`, the convention `nav-counts.ts` set. Brand names, codec names (Mono/Stereo included — see `media-info.ts`), config snippets and example placeholders stay literal.
- **The global `:focus-visible` outline lives in `@layer base`, so a component's own focus treatment overrides it.** Unlayered, it outranked every Tailwind utility: the pill search fields (an `outline-none` input inside a wrapper that lights up with `focus-within:border-accent`) drew a rectangle inside the pill on every tap, since Chrome matches `:focus-visible` on any focus of a text field. An element that sets `outline-none` or `focus:outline-none` must therefore show focus some other way — a wrapper `focus-within:` border or ring, `focus-visible:underline`, or the poster card's `has-[:focus-visible]` shadow — because the global ring no longer rescues it.
- **Below md, search is a page — `/search` (`routes/search.svelte`) — not an overlay** (#140). It was a screen AppShell drew over the current page, which put nothing in history: Back left the page underneath and the search stayed on top of the next one. The top bar's phone button is a plain link to it; the typed query is its `?q=`, so Back from a picked result lands on the same results; Cancel and Escape go back when the page was opened from inside the app and replace it with `/` when it was loaded from the URL (`activeRoute.prevRoute` at mount); an action row (add, sign out) leaves first and runs once the previous page is back, so the add flow opens over that page rather than over search. md and up keep the command palette and the tablet `SearchField`; `/search` loaded at that width renders inline. A layer that is a destination of its own belongs in a route like this one; a layer over a page (a sheet) uses `closeOnBack` below. Neither fakes a history entry: a `pushState` behind Routify's back has to bypass its patched `history` (`useRoutify: false`) and is rewritten by every list page's own `replaceState` of its query, so Back reverted the filters picked in a filter sheet.
- **Every bottom sheet and full-screen layer closes on Back and never outlives its page** (`closeOnBack(isOpen, close)` in `lib/close-on-back.svelte.ts`, called at init; a sheet mounted only while open passes `() => true`). Back is Chromium's `CloseWatcher` (Android's system Back button and gesture, standalone PWA included): the topmost watcher gets it, so nested layers close one at a time — a lookup result's details sheet, then the add flow — and `LookupSheet` drops an expanded sheet to its peek first, as its Escape does; a watcher fires once, so one whose layer stays open is armed again. **Escape stays with each layer's own handler**: Chromium also routes Escape to the topmost watcher, and a watcher spent by an Escape keydown does nothing, or one Escape would act twice (and close a sheet whose Escape only collapses it). `Modal` and `ConfigFormShell` register too, though they are centred dialogs, so a confirm opened over a sheet is the layer Back closes. Where `CloseWatcher` is missing (Safari, Firefox) Back stays a page navigation, and the second rule closes the layer: **an open layer closes when the route's path moves off the one it opened on** — the path only, since a filter sheet rewrites the query on every tap. That rule is what keeps AppShell's layers (the add flow, the bottom nav's More sheet) off the next page; a route's own sheets unmount with it anyway. A new sheet or covering layer calls `closeOnBack`.
- **Back and Forward restore `#main`'s scroll position** (`lib/scroll-restore.ts`, installed by `AppShell`). Routify scrolls `#main` to the top after every render and `#main` outlives every route, so Back from a detail page used to land at the top of a list scrolled a hundred posters deep — and making search a route would have done the same to Cancel. Positions are keyed by the route URL with its query (a list's filters are its query), saved when the store moves (the outgoing page is still in the DOM then), restored only for `popState`, re-applied every frame for 1s so it outlasts Routify's own scroll-to-top and a cached list's first paint, and abandoned at the user's first wheel, touch, pointer or key. A link or a page's own `replaceState` starts at the top as before. A page with a scroller of its own passes it under its own name — the phone search page's results list does (`restoreScrollOnBack(listEl, "search")`), so Back from a picked result lands on the same row; it mounts with its route, so the store's first emission is the traversal that brought it back. A page whose list is not cached by the time it renders comes back as high as it has grown within that second.
- **`#main` (`AppShell.svelte`) is `relative`, and must stay positioned.** It is the app's one scroller (the shell is `h-dvh overflow-hidden`), and a scroller clips an absolute descendant only when it, or something between them, is that descendant's containing block. Unpositioned, every `sr-only` label with no positioned ancestor resolved against `<body>`, escaped the clip and stretched the document: the book detail page's editions table (one `LangChip` label per row) grew it to ~3600px and the browser drew a second scrollbar beside `#main`'s.
- **`INPUT_CLASS` (`lib/form.ts`) is the one text-input class**, after six byte-identical copies. A read-only field keeps its colours — it still has to be readable and selectable — but drops the I-beam and the focus ring, both of which invite an edit that cannot land.
- **The counts endpoints are faceted, and each facet reads its own `*_total`.** `/movies/counts` and `/series/counts` take the list's own filter params, and every tally arrives counted with the *other* facets applied and its own left out. Sharing one `total` across the status, type and monitoring "all" rows is wrong the moment two facets are filtered — and counting a facet against its own selection is worse: it zeroes every row but the chosen one, so the dropdown can never be changed back. `total` stays the unfiltered library, which is what the page header and the empty state want (`libraryTotal`, not `counts.all`).
- **`series_status` is two values, not three — `upcoming` is gone end to end.** The tab read `0` forever while staying clickable, which is indistinguishable from a filter that does not work, and it was reported as one in the same breath as `importing`, which genuinely was. `continuing` already answers "is this show still on", and TVDB only reports `Upcoming` before a premiere — a state a library of shows someone chose to follow never holds. Removed from the ent enum, `TVShowFacets`, `tvshow.Counts`, the `TVShowCounts` response and its `required` list, the `series_status` response enum, `SeriesStatus`/`TVShowCounts` in `types.ts`, and the toolbar. `normalizeStatus` now folds `Upcoming`/`Planned`/`In Production` into `continuing` through its catch-all. **This is a breaking API change**: a required response field and an enum member both disappeared.
- **A kebab dispatcher is a `switch` with a `never` default.** The menu component owns both the item list and the action union, so an if-chain that misses a member renders a menu entry that silently does nothing — which is exactly how the series detail page shipped "Change quality profile…" with no handler while the card menu had one. `routes/series/[id].svelte` and `SeriesActionsMenu` both switch exhaustively; adding a `SeriesAction` is now a compile error in every consumer.
- **Every detail page — movie, series, artist, book, book series — has a History tab** (`components/shared/DetailHistory.svelte`, one owner prop each: `movieId`, `seriesId`, `artistId`, `bookId`, `bookSeriesId`), and its rows lean on `eventSubject().detail` since the title is the page itself: the album on an artist page, *Vol. n · Ebook* on a series. The book page had no tabs before it; its Overview is everything that page used to be.
- **Detail-page tabs are swipeable on phones and tablets** (`lib/swipe-tabs.ts`, `use:swipeTabs` on the region under the tab bar, which is `min-h-[60dvh]` so a short tab still has somewhere to swipe). Touch only, below `lg`, judged on `touchend` from passive listeners so a vertical scroll is never held; a flick must be ≥60px, mostly horizontal and under 700ms, and is ignored when it starts on a horizontal scroller, a form field, `[data-no-swipe]`, or within 24px of either screen edge (the OS back gesture). While mounted at a touch width it sets `overscroll-behavior-x: none` on the **root element** — Chromium otherwise reads the rightward flick as its own back navigation and leaves the page; the same value on `#main` does not stop it. A new tabbed page passes its tab keys and its tab track (`track`, to scroll the landed tab into view) to the action, and gives the track `overflow-x-auto` so the bar can hold more tabs than the screen is wide.
- **Never gate a file action on `have_episodes`.** The rollup excludes specials by design (see `media-lifecycle.md`), so a specials-only show reports 0 and the series detail page greyed out Rename and Delete-all-files over an episode set that was not empty. Gate on the set the action will actually operate on — `seriesFileEpisodes`, which spans every season.
- Bundling: `pnpm exec routify build` then `node web/app/esbuild.config.mjs` (esbuild + esbuild-svelte) → `web/static/dist/spa.min.{js,css}`. Scalar API-docs bundle is separate: `web/static/js/docs.js` → `docs.min.js` + `docs.min.css`. `task build:js` emits both.
- **The SPA is installable via `web/static/manifest.json`, and that is the whole PWA.** It is `.json` rather than `.webmanifest` because Go's built-in MIME table has no entry for the latter and the distroless image has no `/etc/mime.types` to fall back on; browsers accept any JSON media type. There is deliberately no service worker (offline was declined; Chrome no longer requires one to install), no install nudge, no push and no share target. `icon-maskable-512.png` is the favicon flattened onto `--bg-deep` so Android's adaptive mask never exposes the tile's transparent corners. `web/embed.go` lists directories one by one, so the manifest needed its own `//go:embed` line — the spec in `spa_test.go` is what catches that line going missing. `TopBar`, `FullScreenPanel` and the phone search page (`routes/search.svelte`) pad `env(safe-area-inset-top)` for the standalone status bar.
- **Players & readers (Account) and the Hardcover key.** `AppAccessCard` maps `kind` to `/account/subsonic-password` or `/account/opds-token` through `lib/app-access.ts`; the secret is in the POST response only and `withoutSecret` keeps it out of the query cache. The server row is `location.origin` (`/opds` appended for OPDS) and the username is the account email, so the OPDS card is catalog URL + email + token, never a URL carrying the secret. A book call that cannot reach Hardcover answers `503` with `code: hardcover_not_configured` or `hardcover_key_rejected`; `hardcoverIssue` (`lib/music-books-lookup.ts`) reads it, `ProviderKeyNotice` renders it and links to `/settings/metadata#hardcover` (the `streamline:focus-field` session key carries the focus across a client-side navigation), and a failed book scan reads `ImportScan.failure_code` for the same link. Music and book import scans adopt in place only, so `NewImportForm` offers no rename or transfer mode for them.
- **Default profiles are one control for every tab.** `ProfileDefaultControl` + `lib/profile-defaults.ts`: music has one default (`POST .../default`), video sends `?media=movie|series`, books `?kind=novel|bd|comic|manga`; a profile reports the kinds it holds in `default_for`, and the "Default · kinds" badge replaces the per-kind buttons.
- TailwindCSS v4 (`@tailwindcss/cli`): `web/static/css/input.css` → `style.css`, scanning `web/app/**/*.svelte` (`task build:css`).
- Frontend deps via pnpm (`package.json` is a manifest only, no scripts). JS/CSS lint+format is Biome (`biome.json`) over `web/static/js` + `web/static/css` only — tabs width 2, double quotes, semicolons.
