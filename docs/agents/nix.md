# Nix

> **Read before touching** `nix/**`, `flake.nix`, `flake.lock`, `nix/toolchains.json`, `.github/workflows/renovate-pins.yaml`, the toolchain declarations (go.mod's `go` directive, `package.json`'s `engines.node` and `packageManager`), or `renovate.json`'s custom managers.
>
> **Covers** — the flake outputs, the derived hashes, the image digests renovate writes, toolchain pinning and overrides, how renovate and `renovate-pins.yaml` keep them moving, `GOTOOLCHAIN`, the package source fileset, the NixOS module's config mutability, ffmpeg and `ReadWritePaths`, and the lint check.
>
> **Load-bearing** — hashes and `toolchains.json` are derived, never written by hand; an image digest stays literal beside its tag in each `FROM`; both package FODs are named after their inputs; the locked nixpkgs decides which toolchain lines exist and upstream decides the patch; `engines.node` stays a `>=` floor; `packageManager` never moves without the lockfile.

- `nix/` holds the whole surface: `package.nix` (buildGoModule over a `frontend` derivation that runs the same pnpm/esbuild/tailwind pipeline as `build:js`+`build:css`), `go.nix` + `node.nix` + `pnpm.nix` (the toolchain pins, with `toolchains.json` holding their override hashes), `options.nix` + `common.nix` (shared by both modules), `module.nix` (NixOS), `hm-module.nix` (home-manager), `test.nix` (two-node VM test). Flake outputs: `packages.streamline`, `overlays.default`, `nixosModules.streamline`, `homeModules.streamline`, `checks.{build,nixos,home-manager,lint}`.
- **Two hashes and a version are derived, not written.** `pnpmDeps.hash` moves with `pnpm-lock.yaml`, `vendorHash` with `go.sum`, `version ? "X.Y.Z"` is rewritten by `release:app:changelog` (`app:tag` refuses a mismatch), and `nix/toolchains.json` follows the declared toolchain versions. `deploy/Dockerfile`'s golang and node images are not derived: renovate's dockerfile manager writes each digest with its tag, which needs both spelled out in the `FROM` line — a digest assembled from an ARG is invisible to it, and a tag moved without its digest silently keeps building the old image. `.github/workflows/renovate-pins.yaml` derives all but the version, on renovate's own branches. **Both package FODs are named after their inputs** (`inputsId` in `nix/package.nix`: `pnpmDeps` after `pnpm-lock.yaml`, `pnpm-workspace.yaml` and the pnpm version, `goModules` after `go.mod`, `go.sum` and the Go version) — a fixed-output path is only its name and declared hash, so under a fixed name a stale hash still resolves to the old output wherever that path is cached, and the homelab builder passed exactly such a `pnpmDeps.hash` after the pnpm 12.11.2 bump. The lint check shares the package's `goModules` path rather than fetching it twice. `goModules` takes `preBuild = ""`: buildGoModule hands it the package's `preBuild`, whose `cp ${frontend}/…` made vendoring wait on the frontend build, and so on a source-built Node whenever `engines.node` is ahead of nixpkgs. CI's `nix` job filters on exactly those inputs, so a lock change is what triggers the expensive check.
- **Upstream decides each toolchain's patch; `flake.lock`'s nixpkgs decides which lines exist.** The declarations are the source: go.mod's `go` directive, `package.json`'s `engines.node` (a `>=` floor, stripped) and `packageManager`. `nix/{go,node,pnpm}.nix` take the line from it — `go_1_NN`, `nodejs_NN`, `pnpm_NN` — and **throw when the locked nixpkgs has no such line**, so a new Go minor or Node/pnpm major waits for nixpkgs. Within the line, nixpkgs' package is used as-is when it is already on the declared version and **overridden onto it otherwise, in either direction**: Go and Node are rebuilt from upstream's source tarball; **pnpm is not** — it installs pnpm's own `@pnpm/exe` binary (what `pnpm/action-setup` and the Dockerfile's `npm install -g pnpm` fetch anyway), patched with `autoPatchelfHook`, because pnpm 12's Rust build recipe moves between patches (12.10 began generating `cas-loader.mjs.inc` with esbuild before `cargo build`, a step nixpkgs' 12.9.0 recipe lacks) and a version override broke on exactly that. All hashes sit in `nix/toolchains.json` keyed by version — Go and Node one source hash each, pnpm npm's `integrity` per platform. The devshell, `nix build`, CI and the container therefore run one exact version, without a security patch waiting on a nixpkgs channel — Go 1.27.2 sat in `nixos-unstable-small` for days while `vulncheck` stayed red and the old equality throw kept go.mod from moving. An overridden Go or Node is compiled from source and is not on cache.nixos.org: the homelab builder keeps it for CI, and an overlay user whose nixpkgs differs builds it once. `nodejs_NN` is a symlinkJoin, so `node.nix` overrides `nodejs-slim_NN` and rebuilds the wrapper, and the override drops `--shared-brotli` so Node builds the brotli it bundles — a patch release can carry a newer one than nixpkgs ships, and 24.22.1's `node_zlib.cc` names a decoder error code brotli 1.2.0 leaves reserved; `package.nix` passes its own pnpm to `fetchPnpmDeps` (whose store layout follows the pnpm that runs it) and exposes all three as `.#streamline.{go,nodejs,pnpm}`.
- **Renovate bumps the declarations from upstream; `renovate-pins.yaml` derives the rest.** Two regex managers (`customManagers` in `renovate.json`) move Go (`golang-version`: the `go` directive of every go.mod, the extension SDK's and the echo fixture's included) and Node (`node-version`: `engines.node`, every workflow `node-version`), each grouped (`groupName` `go`/`node`) with the dockerfile manager's image of the same toolchain, which moves tag and digest in one commit — one PR per toolchain; pnpm's `packageManager` rides the existing npm/`pnpm/action-setup` group, joined by a third regex manager for the Dockerfile's `PNPM_VERSION` (npm datasource) — Node ships no corepack from 25 on, so the image installs that exact pnpm from npm. pnpm 12 records its own version in `pnpm-lock.yaml` (`packageManagerDependencies`), so `packageManager` never moves without the lockfile — renovate's npm manager regenerates both, and a hand bump needs `pnpm install --lockfile-only` or every `--frozen-lockfile` install (CI, the Dockerfile) fails with `ERR_PNPM_FROZEN_LOCKFILE_WITH_OUTDATED_LOCKFILE`. The built-in gomod/npm/github-actions managers stay `enabled: false` for go/node/golang, or each would bump one copy in a PR of its own. A Go minor and a pnpm or Node major wait on the dependency dashboard — each is a new nixpkgs line. Renovate writes the workflow copies itself because a push made with the Actions token may not touch `.github/workflows/`. On renovate's branch `renovate-pins.yaml` then checks that the locked nixpkgs has each line and that every copy agrees with its source (an image tag Docker Hub has not published yet fails here until renovate's next run adds it), rebuilds `toolchains.json` from scratch (an entry only for a tool nixpkgs has on a different version, so a lock that catches up drops it; Go and Node by `nix store prefetch-file`, pnpm by reading npm's `integrity` off the registry — no build), and derives `pnpmDeps.hash` and `vendorHash` — in that order, since both build through the pinned pnpm. **`renovate-pins.yaml` pushes with a GitHub App token when `vars.PINS_APP_CLIENT_ID` + `secrets.PINS_APP_PRIVATE_KEY` are set** (Contents: write only, setup in `renovate-pins.yaml`'s header): a push made with the Actions token creates CI runs that sit at "approval required", so every derived commit left its PR without checks until the owner approved them; without the App it falls back to that token. `renovate.json`'s `gitIgnoredAuthors` names the bot's commit email, or renovate would treat each derived commit as a human edit and stop rebasing the branch; it recreates the branch over them and the workflow derives again. `engines.node` stays a **`>=` floor**, for anyone building without the devshell; pnpm enforces a project's own `engines` unconditionally, so an exact value there breaks `pnpm install` for everyone not on that patch.
- **`GOTOOLCHAIN = "local"` is set three times, deliberately.** The `golangci-lint-fmt` wrapper treefmt runs exports it in `flake.nix`. `buildGoModule` sets it for `nix build` (`pkgs/build-support/go/module.nix`), and `flake.nix`'s devshell env sets it again because nothing else does for `nix develop` — the default, `auto`, silently downloads whatever toolchain go.mod asks for, which would paper over exactly the mismatch `nix/go.nix` exists to refuse, in the one shell meant to be the reproduction.
- The package `src` is a fileset that **excludes** every frontend build output (`web/static/dist`, `style.css`, `docs.min.*`, `.routify`, `lib/paraglide`) — they are gitignored, so leaving them in would make the source hash depend on whether someone ran `task build:js` locally. `.golangci.yml` rides along for the `lint` check only; `e2e/` is deliberately out, since its rod deps are not in the vendored module set.
- **The config file is runtime-writable, so the module picks a side.** `mutableSettings = true` (default) seeds `settings` into `${stateDir}/config.yaml` on first start and never touches it again — the UI works, and a rebuild does *not* re-sync. `false` serves the store file and forces `read_only`, which is the only way a store path is safe: without it `config.Update` fails on a read-only filesystem instead of returning `ErrReadOnly`.
- `ffmpeg.path` is a **directory** (`resolveBinary(dir, "ffprobe")`), not the executable. `hardwareAcceleration.enable` only opens `/dev/dri` — `ffmpeg-headless` still cannot use it, and `ffmpeg-full` is the build carrying VAAPI *and* libvmaf (without which `transcoding.verify.min_vmaf` parses and silently never runs).
- `ProtectSystem = "strict"` means `ReadWritePaths` is load-bearing: it is the union of `stateDir`, the absolute `data_dir`/`movie_path`/`series_path`/`download_path`/`music_path`/`ebook_path`/`audiobook_path` derived from `settings` (a library path only when it is set there: granting a binary default such as `/media/music` would name a directory that may not exist), and `extraReadWritePaths` — which **adds** rather than replaces, because a computed `default` on a plain list option would silently drop the derived paths the moment a user set it. A library root added only through the UI is never granted. A path that does not exist yet fails the unit with a mount-namespace error, not a streamline error.
- The `lint` check is `packages.streamline.overrideAttrs` running `go tool golangci-lint`, not a standalone `runCommand` — golangci-lint type-checks, so it needs the module cache and the `//go:embed` assets buildGoModule already arranges. The old standalone check had neither and only ever reported "could not import entgo.io/ent" from a network-less sandbox.
