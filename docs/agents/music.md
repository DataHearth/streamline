# Music

> **Read before touching** `internal/media/music/`, `internal/metadata/musicbrainz.go`, `internal/metadata/mblimiter.go`, `internal/importer/album*.go`, `internal/importer/pack.go`, `internal/rss/music_feed.go`, or any `/music/*` handler.
>
> **Covers** — the artist/album/track model and MusicBrainz, cover resolution, adoption, acquisition and imports, WAV conversion, two-phase add and hydration, the canonical edition, shared albums, the monitor policy, overviews and artist photos, searches and discography packs. The tags written into the files are [`music-tags.md`](music-tags.md).
>
> **Load-bearing** — `metadata_fetched_at` NULL is the one "tracks not here yet" marker; an unhydrated or unreleased album is never searched; every status write filters on the status it moves from; a terminal import failure parks an album `failed`, never re-grabbed automatically; a release group is one album however many artists it credits.

Third vertical, mirroring the TV tree: `Artist → Album → Track`, with `MediaFile.track` as the file edge. Metadata is MusicBrainz (`metadata.NewMusicBrainz`, no key, a 1 req/s limiter and a mandatory User-Agent; `metadata.musicbrainz_url` points it at a self-hosted mirror — the server root, `/ws/2` is appended — and `metadata.musicbrainz_interval` paces it; both on Settings → Metadata, read at construction, restart required) and an album is a MB **release-group**; an album cover is resolved by `music.Service.resolveCover` (`covers.go`) from the first source that yields an image: a picture embedded in one of the album's files (`audiotags.Picture`), a `cover|folder|front.jpg|jpeg|png` beside the first media file (neither ever the tag writer's own copy, told apart by its recorded hash), Deezer by the canonical release's barcode (`Album.barcode`, kept from MusicBrainz at add time; `metadata.NewDeezer`, keyless, 10 req/s), Deezer search (only when the first hit's artist matches, via `library.TitleMatchesStrict`), then the Cover Art Archive release-group front. Local sources store through `imagecache.Store.Put` and run even when a cover is cached (the album's own art outranks a downloaded one); the remote ones only when none is, and a failing source falls through to the next. It runs in the background (`ResolveCoversInBackground`, behind the `music.CoverResolver` interface that bulkimport and the importer call after adoption/import) and never fails the add; a metadata refresh asks the remote sources again for every hydrated album (`refreshCoversInBackground`): a local cover still wins and a remote miss keeps the cached one. Span `music.resolve_cover` carries `cover.source`, counter `streamline.music.cover_resolutions{source}`. Library covers go through the posters proxy under the `albums` kind and artist photos under `artists` (a monogram when there is none). `Add` is **two-phase** (below): the request fetches only the artist and its release-group list and returns album stubs; a background worker fills the tracks. An artist's `path` on the wire is derived per response from the music root in force (`artistPath`: root + sanitized name) and is not a column: the stored copy kept naming the root the artist was added under. `Track.duration` is **seconds** (MusicBrainz reports milliseconds; the client divides), the release track's length or, when the release gives none, its recording's and the spec, SPA and ent field all agree on that. Music profiles are their own config family, `music_quality_profiles[]` + `music_quality_default_profile`, edited through `/music/quality-profiles` (never `/config/*`; the first profile created becomes the default, `POST …/{name}/default` moves it). A profile ticks **tiers** (`hires > lossless > high > standard > low`, stored best first) and names the `preferred` one, the upgrade ceiling; there is no `other` tier. `internal/quality/audio.go` is the one classifier (`AudioTierOf`, `AudioFine`, `MusicProfile.Accepts/Score/Replaces`), and the SPA's `releaseTier()` is written to the same rule. `library.ParseMusicRelease` reads codec, bit depth, sample rate, rate and VBR preset into `Facts` plus the display label `Source` (`FLAC 24/96`, `MP3 V0`); `JudgeMusicRelease`/`ScoreMusicRelease` take a `MusicScope` (a discography is rejected for an album search and kept for an artist-level one) and a release whose name states no quality stays in the list, rejected, instead of landing in a catch-all tier. `MediaFile.quality` is the tier (`hires|lossless|high|standard|low`, empty when it could not be established), `format` the extension. Album art for a title **not in the library** (the add flow, a request panel) comes from the one lookup proxy, `GET /posters/lookup/{artists|albums|books}/{key}/poster.jpg` (`internal/artwork`, see HTTP Routes); artist photos in the library are the `artists` poster kind. `POST /music/albums/{id}/search` and `/grab` are the manual search and grab (member-only; the grab body is a search item's `release` handle intact, answered with an empty 202). `POST /music/albums/{id}/release-files` takes the same body and lists the release's files against the album's tracks before any grab (`download.ReleaseFiles`: the grab's own `checkReleaseSource` + `resolveTorrentSource` + `decodeTorrentFiles`, nothing added to a client; `library.MatchTrackByName` reads disc folder/prefix, number, then a loose title off each name, so it is a preview — the import matches by tags). One indexer request per call, so only ever on a person's tap; a magnet's list is fetched from its swarm by the download client when it can (Deluge's prefetch; the builtin engine's `ProbeMagnet`, a client of its own for at most 30 s, never the live one, and never on a grab), else `422 files_unavailable`, an indexer that does not hand a readable `.torrent` over `422 torrent_unreadable`. A grab without `replace_existing` already fills only the tracks without a file (`planAlbumImport`), which is the SPA's *Download missing tracks only*. A discography has it too: `POST /music/artists/{id}/release-files` (`music.Service.ArtistPackFiles`) groups the audio by `library.PackAlbumDir` and matches each folder with `library.MatchPackDir` against `ListPackAlbums` — the pack importer's own two functions, moved out of `importer/pack.go` so the preview cannot drift from the import — then each file to a track by name; a folder naming any other album of the artist is reported skipped. TV has the same pair for packs: `POST /series/{id}/release-files` and `/series/{id}/seasons/{number}/release-files` (`tvshow.Service.PackReleaseFiles`) match each file with `library.MatchEpisodeInSeason` over video files ≥ `library.MinEpisodeSize` — the selective keep-set's own candidate rule and the importer's matcher, so the preview is what a grab keeps — and mark an episode `wanted` by `wantedAiredEpisodes`, what a grab without replace fetches; *Download missing episodes only* is that grab, and `takesPackFile` leaves every episode holding a file in place. `GET /music/artists` is filtered (status, monitoring, `genre`, query), sorted, paged and faceted in SQL (`/music/artists/counts`, the faceted-counts convention of `/series/counts`, plus `genres`, and `letters`: the artists per letter under every filter, from which the SPA works out the page a letter opens on) and its items carry their albums as tiles with no tracks. The name sort is by the displayed name, never `sort_name`, through the `sort_letter` SQL function first, so `#` (anything not starting A–Z) comes before A and each letter is one run; `sortLetter` in `web/app/lib/music-books.ts` must file names the same way; the detail, patch and refresh responses carry the tree, each track with its `featuring` only — `writers` and `artists` come from `GET /music/artists/{id}/track-credits`, which the Discography tab fetches behind the page (under its own cache key outside the `["music"]` prefix, refetched only every minute while the artist hydrates, once more when hydration ends and on an edition pick, so a monitor toggle does not reload megabytes of credits), and `GET /music/albums/{id}`, which fills the open release until that answers, since every track's credits are hundreds of uncached page reads on an artist's first load on the homelab's Ceph volume (about 30 ms per read), and a kind filter over the track index saves nothing because the kinds share pages; the `(kind, track)` index is what makes `featuring` alone cheap.

**Adoption** is `ImportScan.kind=music` through bulkimport: every folder directly holding audio files is one candidate (its `CD1`/`Disc 2`/`Disk1` subfolders fold into it, `library.DiscFolderNumber`, unless the parent is the scan root), tags are read with `internal/library/audiotags` (TagLib; the scan never writes, and a commit writes tags only when it asks, `write_tags`, default off), the majority `(albumartist|artist, album)` pair is matched through `MusicProvider.SearchReleaseGroups`, and commit adopts in place (`source=orphan`) after seeding the artist through `music.Service.Add` with `Monitor: "none"`; `mode=rename` is refused for music **and book** scans (`ErrRenameUnsupported`, 422, checked before the Hardcover key), each review row carries `tagged_year`/`format`/`size` and a live `artist_id`, an `existing` row that joins the library's album ends `attached` not `created`, a release group missing from the artist's discography fails that album with a message, commit adopts the parent's own files and every disc subfolder's, a file with no disc tag taking its folder's disc number, and `AdoptAlbumFiles` never moves an album out of `downloading`. Music **does** refresh media servers (`mediaserver.KindMusic`): album and pack imports, music bulk-import commits, renames, track-file deletes and artist deletes-with-files all go through `Refresher`/`RefreshInBackground`. Plex rescans only `artist`-type sections (path match first, then every `artist` section; none at all is an error, never the movie section), Jellyfin/Emby refresh everything. **Subsonic is not part of Streamline**: it is an extension in a repository of its own, and core holds none of its data ("OPDS and Subsonic are projects of their own" in `docs/agents/extensions.md`). **Acquisition**: `library.ParseMusicRelease`/`ScoreMusicRelease` (tiers, discographies rejected for an album scope), `indexer.Manager.SearchAlbum` (cat 3000), `music.Service.SearchAlbumReleases`/`GrabAlbumRelease` over `download.GrabAlbum`, which links the record's `album` edge; `Store.SetAlbumStatus` and `RecordAlbumImportSuccess` filter on the status they move from. **A terminal import failure parks an incomplete album at `failed`** (one holding every track goes back to `available`, an uploaded record's goes back to `wanted`, since a bad upload is no reason for the searches to stop; the orphan sweep splits on the same `completeAlbum` predicate) with `Album.failure_reason` (`RecordImportFailure`, a pack's linked albums too, and a held record rejected without requeue), mirroring movies: the missing searches, RSS and `search-now` read `wanted` only, so a failed album is never re-grabbed automatically — it used to go back to `wanted` and the next pass grabbed the same release again. A manual grab or pack (`SetAlbumStatus` from `wanted|paused|failed`, which clears the reason) and `POST /activity/history/{id}/retry` (back to `downloading`) take it out; the artist rollup and its SQL twin count `failed` as `wanted`. The album importer refuses a **CUE disc image** (`library.CueImage`: the folders holding a `.cue` hold at most half as many audio files — `.ape`, `.wv` and `.wav` included — as the album has tracks, so one image per disc and one per vinyl side are both caught; a one-file-per-folder rule let `Side A…D.flac` 2LP rips through to fail as unmatched) as `ErrCueImage`, terminal, *before* matching — the image's tags can name track 1, and the whole disc would be imported as that track. **One image is never downloaded to be refused**: a name stating it (`image+.cue`, `img+cue`; never `tracks+.cue`) is rejected by `JudgeMusicRelease` at either scope; an album grab of a `.torrent` reads the file list it already decoded and refuses with `download.ErrCueImage` (`grab_rejected`) before the client is contacted, which `searchAlbum` answers by trying the next accepted release in the same pass, no strike; a magnet is checked by the monitor's `RejectCueImages`, run before `CheckStatus` each tick, once its client lists the files (each record listed once, remembered in memory) — the torrent and its data are removed, the record is failed **rejected** (the blocklist) and the album requeued `wanted`, no strike. The album importer (`importer/album.go`) matches files to tracks through `library.TrackMatcher`: by tagged `(disc, track)` then title, unless at least two files, and more than name the track there, name *another* track's title at their number — an edition with interludes between the songs — when every file matches by title alone (a title naming no track of the album is no evidence either way, so a translated release keeps its numbers; the importer's `track` hold check catches every title that differs and every file it could not place on a single album, on a pack only a minority when at least half agree, and the Resolve dialog then lets a person pick each file's track, `GET /downloads/{id}/track-plan` and `track_assignments` on the resolve); bulk-import adoption and both release-files previews build the same matcher over the whole release. An empty plan whose files all hit filled tracks is `ErrTracksHeld` (an `ErrDestExists` to `classify` and the pack importer, with a message that says what happened), renames per `library.music_naming` (`{Artist}` `{Album}` `{Disc}` `{Track:02}` `{Title}` `{Year}`, and per file `{Quality}`, the tier, with `{BitDepth}` and `{SampleRate}` in kHz for a measured lossless file: `MediaFile.bit_depth`/`sample_rate`, recorded by the import and adoption probes and backfilled by `media-probe`, `sample_rate` NULL meaning never measured) and queues each file for its tags, which the engine writes before the media servers are told. The tags themselves are the **music tag engine** (stub below). **Automation**: `rss/music_feed.go` gates on 3000–3999 *after* 3030 (audiobooks) is carved out, `SearchMissing` and `RefreshStale` (every artist not refreshed in 24h, ended by a rate limit) are the `music-missing-search` and `music-metadata-refresh` jobs (books have the `book-*` pair; RSS for both still rides `movie-rss-sync`). **Requests**: `media_type` artist and album carry `media_mbid` with `media_id=0` (artist MBID, release-group MBID; there are no author requests); the active-uniqueness index is partial per key (`media_id <> 0` / `media_mbid <> ''`); approving an artist adds it monitored `all` under the reviewer's profile, and the request flips to `available` on the artist's first imported album (`MarkRequestsAvailableByMBID`), not when the discography is complete. **An album request's `artist_mbid`/`artist_name` are the requester's hints and are never trusted**: approval and `GET /requests/{id}/metadata` resolve the artist from `GetReleaseGroup(media_mbid).ArtistMBID`, approval overwrites the stored pair with the verified one (`ApproveAlbumRequest`, one statement) and keeps the typed wording in `requested_as`; a missing artist is added with `Monitor: "manual"` and only that album monitored, an artist already held keeps its own profile, and a release group not on the artist (after one `RefreshOne`) answers `422 code: album_not_found` with the request left pending. `GET /music/search/releases` (`MusicProvider.SearchReleaseGroupsFreeText`, memoised 10 minutes) is the release-group picker for the import review and the request flow.


**A WAV is converted to FLAC at import, never held.** `library.ConvertsWAV(prober)` (`ffmpeg.enabled`, ffmpeg and ffprobe found, `library.convert_wav`, default on, runtime-editable on Settings → Music) is the one gate: closed, `JudgeMusicRelease` rejects a WAV release with `WAVReason` and an upload refuses the file; open, the album importer converts each `.wav` to a verified FLAC in a hidden folder under the music root and moves it into place, the source only read. `.wav` is not in `audiotags.AudioExtensions`: downloads, previews and uploads list it through `library.IsReleaseAudio`, adoption never does. Detail in `docs/agents/downloads-and-imports.md` (Album imports).

**The music design backend** (contract `docs/superpowers/specs/mb-design/contract-music.md`). **`Add` is two-phase:** it costs `1 + ceil(n/100)` MusicBrainz calls (a 10-minute, singleflight, 32-entry `ArtistDetails` cache shared with `GET /music/search/{mbid}`, so a lookup followed by an add costs one set), creates the artist, its `ArtistMember` rows and one stub `Album` per release group in one transaction, and returns with `hydrating: true`. `Remix`, `DJ-mix`, `Mixtape/Street` and `Demo` release groups are type `other`. The discography browse sends `release-group-status=website-default`, so a release group with no official release — a fan remix compilation, a bootleg live recording — is never an album; `RefreshArtist` prunes the stored albums a refresh no longer lists, deleting one nothing was done with, unmonitoring one holding files, download history or an acquisition event, and leaving one with a co-artist or a hand-set monitor flag as it is (an empty listing prunes nothing). `music/hydrate.go` then fills each album — tracks, label, country, media, bonus/featuring flags, and, when the heavy release call (`inc=…artist-rels+recording-level-rels+work-rels+work-level-rels+place-rels`, response cap `maxMusicReleaseResponse` 8 MiB) succeeds, credits, performers, writers (each with its part: composer, lyricist, writer, arranger) and studio; the album's credit and performer rows fold every recording's in for display, and each track also keeps its own recording's credit and performer rows, which is what the tag writer reads. A heavy success stamps `Album.credits_version` (`library.MusicCreditsVersion`); an album holding files with an older one is fetched again in the background like a NULL `genres`. The release-group call carries `inc=…+genres` and stores the top five as `Album.genres`; hydration also keeps `Album.original_date` (the group's `first-release-date`) and `Album.edition_date` (the canonical release's `date`), both as MusicBrainz writes them (`YYYY`, `YYYY-MM` or `YYYY-MM-DD`; `release_date` stays the parsed one that sorting and upcoming detection read). A person can override the pick per album (`Album.edition_mbid`, `GET` and `PUT /music/albums/{id}/editions`, re-hydrating at once; refreshes keep it, and an edition MusicBrainz stops listing falls back to the pick for an album without files; one holding files is a metadata change, below). **A hydration that leaves every track holding a file moves a `wanted` or `failed` album to `available`** and clears `failure_reason` (`settleCompletedAlbum`, in `SetAlbumHydration`'s transaction; a `downloading`/`paused` album is its record's): re-picking the edition the files are of used to leave a failed album failed, with an `ErrTracksHeld` reason about tracks it no longer lacked, and nothing searches a failed album. It never demotes. A release-group lookup embeds at most 25 releases and does not say when there are more, so one that returns 25 is read again from the paged `/release` browse (`mbLookupReleaseCap`), for the canonical pick and the editions list alike. The canonical release is the earliest **official** one — among releases out the same day the fewest audio tracks, then the fewest audio discs, then the first listed (the standard edition, not a deluxe or a CD + DVD), and `fillRelease` skips video discs (`isVideoMedium`: DVD, Blu-ray, VHS…) unless the release has nothing else, since Feathers & Flesh's live DVD became eight tracks no audio release carries — a partial date ranking after every fuller date inside its period (`releaseSortDate`: compared raw, `2022` sorts before `2022-10-07`, and Omens took a year-only Russian pressing with three bonus tracks over the standard edition, so every 10-track release looked 3 files short), and a re-hydration (`matchStoredTracks`) keeps each recording's row wherever the edition places it, moving a held file's row to its new position and folding the empty twin an earlier re-pick left, never hands a held row to another song at its position (a same-title recording merge excepted), and deletes every stored track the release no longer lists unless it holds a file. **`genres` NULL marks an album hydrated before genres were fetched** — hydration always writes a list, `[]` when there are none: `HydrateAlbum` fetches such an album best effort (a failure is logged and returns nil, since the caller has its tracks; the importer's `hydratedAlbum` calls it for that case too), the sweep's `details` leg and the worker's idle refill backfill the ones holding files (`ListAlbumsAwaitingDetails`, which also lists one whose tracks carry no credited artist, and, files or not, a monitored album whose `aliases` are NULL, since the searches compare release names with them), and a release group MusicBrainz no longer knows keeps its stored facts and gets `[]` (`storedDetails`) rather than being asked for forever (an `album_removed` metadata change when it holds files). **A metadata refresh re-fetches every album of the artist** (`RefreshOne` queues them all) **and never changes what an album's files are matched against on its own**: an album holding files is fetched on the edition it follows (`edition_mbid`, else its stored `release_mbid`), and a release group merged or deleted, an edition merged or deleted, a canonical release that moved, or tracks holding files the release no longer lists are recorded as metadata changes (`docs/agents/metadata-changes.md`) with the album left as it is; an album without files follows MusicBrainz without asking. `hydrateAlbum` takes a mode: `hydrateIfStale` (the importer's `HydrateAlbum`), `hydrateRefresh` (the worker) and `hydrateFollow` (an edition a person picked, or a change followed), which writes what MusicBrainz has now whatever the files. A failed heavy call retries once with the light `recordings+artist-credits+labels` inc and stamps `metadata_fetched_at` but not `credits_fetched_at`; the credits sweep (`RefreshStale`, 20 a tick, releases above `db.MaxCreditsTracks` skipped) retries it later. **`metadata_fetched_at` NULL is the one "tracks not here yet" marker**: `tracks_pending` on a tile, `HydrateAlbum` (the synchronous, idempotent entry the album importer and bulk-import adoption call before matching files to tracks, also removing the album from the queue), the sweep, and the eligibility predicates all key on it — `ListEligibleAlbumsForSync` and `ListWantedAlbums` skip an unhydrated or **unreleased** album (the music twin of "unaired is never missing"; an undated album is released, and `upcoming` is derived from a wanted album dated after today, never stored). The worker is one process-wide goroutine behind `defer RecoverPanic` (its `onPanic` resets the queue, or the dead worker's albums would stay marked queued forever), serves one album per artist in turn, monitored and newest first, backs off for a `Retry-After` and refills from the database when idle (restart recovery, plus `ResumeHydration` at boot). **Three MusicBrainz classes share the one limiter** (`metadata/mblimiter.go`, one call per `metadata.musicbrainz_interval`, default `1s`, `0s` for a mirror with no limit): an interactive caller takes the next token; a context marked `metadata.Prefetch(ctx)` (the lookup art proxy settling a search tile) takes one only while no interactive caller waits, with no gap; a context marked `metadata.Background(ctx)` (the worker, the credits sweep, the scheduled refresh) takes one only while neither waits and not within `backgroundGapFactor` (2) intervals of its last, so bulk hydration is about 4 s per album at the default and a lookup never queues behind either. A 429 from MusicBrainz, or a 503 carrying `Retry-After` or `X-RateLimit-Zone`, is `*metadata.RateLimitedError` (`Retry-After`, a minute when absent or zero), which the handlers answer as `429 rate_limited`; a 503 carrying neither is a server that could not answer (a mirror whose search backend timed out): `metadata.ErrUnavailable`, answered `502 provider_unavailable` by `responseError` with no wait and no hold, the hydration worker pausing a minute and requeueing the album. A rate limit also **holds the prefetch and background classes** for that wait (they fail with the remaining wait, unsent), since calls sent into a refusal are refused too and a page of search tiles kept a person's own lookup landing on 503s — interactive calls are never held, and the SPA never retries a 429 (`lib/query.ts`). The warning names MusicBrainz's `X-RateLimit-Zone`: `global` is MusicBrainz shedding load for everyone. A login lockout answers `too_many_attempts`, never `rate_limited`, which the SPA renders as a provider limit. `hydrating` stays true only while an album has no tracks, or has tracks whose credits are missing and landed under an hour ago and fit the sweep's size cap, so the SPA does not poll for a day over a release whose heavy call keeps failing.

**A release group is one album however many artists it credits.** `albums.mbid` stays globally unique and `Album.artist` is the **owner** (folder, naming, `ALBUMARTIST`, hydration rotation, renames, monitor policy); `Artist.co_albums ↔ Album.co_artists` lists it under every other library artist whose discography carries it — `CreateArtist`/`RefreshArtist` link through `linkSharedAlbums` instead of inserting (a collab used to fail the whole add on the unique index). Everything that *lists* an artist's albums reads owned ∪ co (`db.AlbumOfArtist`, `db.ArtistAlbums`, `artistHasAlbum` for the status twin and the title filter; detail, tiles, packs, search-now, album-request `findAlbum`, an import flipping co-artists' artist requests); policy re-applies and renames stay owner-only. `db.DeleteArtist` hands every shared album the artist owns to its lowest-id co-artist in the delete's own transaction, files in place; `Service.Delete` leaves those albums' files and covers alone and re-queues their tags (the album artist changed). Each track's own credited artists (before any `feat.`) are `MusicCredit` kind `artist`, written with `featuring` from either release call; they lead the `ARTIST` tag unless they are the owner alone, and the wire carries them as `MusicTrack.artists` (the album's linked artists as `artists`, only for a shared album).

**Monitoring is a policy** (`Artist.monitor` all/future/manual/none, no `monitored` flag): `PATCH` re-applies it to the existing albums in one transaction and never touches `status`; new release groups on add and refresh follow it (`future` = undated or dated after today); **`all` and `future` only ever monitor the release types in `library.music_monitored_types`** (runtime-editable, default `[album, ep, single]`, Settings → Music), the others land unmonitored — `monitoredFor` at seed time and `db.applyMonitorPolicy` on a re-apply share the rule, and the setting reaches existing artists only through a re-apply (`PATCH monitor`, or `POST /music/monitored-types/apply`, admin, which re-applies every `all`/`future` artist in one transaction but **skips every album whose flag was set by hand** — `PATCH /music/albums/{id}` and album-request approval set `Album.monitor_pinned`, and only a `PATCH monitor` on the artist clears the pins, since choosing a policy is starting over); `Album.monitored` stays the only flag searches, RSS and imports read. The artist's own `status` field is a rollup (`wanted|downloading|available`, over monitored, non-upcoming albums, `music.artistStatusAt`). The list's status filter and its facet counts ask a different question, what an artist **has** (`db.artistHas`): `wanted` is any monitored, released album wanted or failed, `downloading` any downloading or paused, `available` neither, so an artist can be under both of the first two and the counts overlap. **The overview is Wikipedia in both SPA locales**, fetched when the artist is added and again on every refresh, a refresh that finds nothing keeping what is stored, from the Wikidata item MusicBrainz links, stored as `overview`/`overview_source` (en) and `overview_fr`/`overview_source_fr`, served for `?lang=` with English as the fallback and the source following the text actually served. The **artist photo** is Deezer by MusicBrainz's own link unless another MusicBrainz artist links the same page (`metadata.ArtistLinkProvider.DeezerArtistShared`: Deezer merges namesakes, and the 60s UK Nirvana got the grunge band's face), else by name only when exactly one hit folds equal to it (never "first hit wins"), and what that leaves unsettled takes MusicBrainz's own Commons `image` rel (`ArtistArt`) or no photo — the same rule as the lookup proxy, its MusicBrainz calls at `metadata.Prefetch` priority off the add request; stored under the `artists` poster kind (`Store.Fetch` sends streamline's User-Agent, which Wikimedia requires); lookup art for hits not yet added is `internal/artwork`'s, fed by `artwork.Remember` from `SearchArtists` and `LookupArtist`. `GET /music/tracks` is the search surfaces' track list, the `/episodes` twin.

**Searches and packs.** `POST /music/albums/{id}/search` keeps every release the profile rejects, flagged with a reason ("tier not in the profile", "quality is not stated in the release name", and "is not named for this album and artist" when `library.ReleaseNamesAlbum` does not read this artist and this album off the name, under any of the artist's names and the album's titles — read with and without the bracket groups a tracker opens a name on (RuTracker's `(Groove Metal) [CD] Artist - Album - 2026, FLAC`, whose first ` - ` otherwise made the whole prefix the artist), a scene name with no ` - ` by finding the artist's words at its head, `&` and `and` equal, and indexer titles HTML-unescaped at both adapters (`Feathers &amp; Flesh`). **The automatic search grabs from this same list** (`searchAlbum` calls `SearchAlbumReleases` and takes the first release not rejected), so a name that cannot be read is rejected for a person too: `Kinobe.Slip.Into…` showed as acceptable for Кино and `EPHEL DUATH-The Painter's Palette` for IU's Palette. A Cyrillic name is also compared under the scholarly romanization and its look-alike letters (`cyrillicSpellings`: `Sladkaja_žizn`, `CKA3KA`)) and drops a discography (rejected by scope, not listed). When the artist name or album title is not in Latin script and the library holds a Latin one (`library.LatinAlbumQuery`: the sort name read forwards, the first Latin alias, one without diacritics first), it sends one more query per indexer, without the year, and when nothing so far names the album a last one for the artist's Latin name alone: trackers file a translated album under names MusicBrainz does not list (Этажи is "Floor" on two of them), and `Molchat Doma` found eleven releases where both album queries found none. Each of those searches is filtered on its own (`answeringQuery`): nothing is listed from an indexer none of whose results opens on the artist or could be the album, since The Pirate Bay answers a term it cannot read with the hundred most seeded torrents of the category and RuTracker matches one on the year alone. A release name's creator and title parts are also read under the other names a tracker writes into them (`alternateNames`: `Kælan Mikla (Kaelan Mikla)`, `ДахаБраха [DakhaBrakha]`, `Mánadans / Manadans`), and `æ ø ð þ ł ß` compare as the letters they are typed as; `/music/artists/{id}/browse` is the inverse — only discographies whose artist part (`library.SplitCreatorTitle`) folds equal to the artist. `search-now` on an album/artist/track is a 202 that runs `searchAlbum` in a goroutine (waiving the cooldown and failure cap by not consulting them; an available, upcoming or in-flight album is a no-op). **A discography pack is a `DownloadRecord` with an `artist` edge and the albums it expects on the `albums` many-to-many** (`download.GrabArtistPack`: it links monitored, released, hydrated albums that are wanted, paused or failed, refuses with `ErrNoWantedFiles` before touching the client when none qualify, and marks them `downloading`); `importer/pack.go` groups the audio files by folder (a `CD1`/`Disc 2` subfolder belongs to its parent), matches each folder to a **linked** album by folded title, aliases included, the year it names deciding between two albums of one title — no provider call — and runs the ordinary album import for each with `KeepRecord` (a folder naming no album of the artist, or one an earlier folder took, holds the record first under the `folder` check, unless verification is bypassed: `GET /downloads/{id}/folder-plan` and `folder_assignments` on the resolve let a person pick), then `CompletePackRecord` completes the record and returns the linked albums no folder named to `wanted` with no strike. Rename (`music.Renamer`, `library.Renamer` keyed by artist) renders `library.music_naming` with the importer's own helper from database metadata only; `DELETE /music/tracks/{id}/file` checks every path against `library.music_path` first (`409` if any lies outside, nothing deleted) and moves a `available` album to `wanted`.
