# Downloads, imports & adoption

> **Read before touching** `internal/bittorrent/`, `internal/importer/`, `internal/download/adopt.go`, or `internal/mediaserver/`.
>
> **Covers** — the builtin engine's memory bounds, peer-socket ownership and port rebinding; import verification and the `held` record lifecycle; adopting a manually-added torrent (proposals, identify, preview, replace); and the post-import media-server refresh.
>
> **Not here** — which files a grab asks for (`selective-file-download.md`), whether a release beats a file (`quality-scoring.md`).

## Builtin torrent engine
- **The peer pool is capped by `applyMemoryBounds` (`internal/bittorrent/bounds.go`), and the caps are constants on purpose.** anacrolix's defaults — 50 established conns per torrent, 100 total half-open, 500 known peers per torrent, 64 MiB of unverified piece data — are sized for a desktop. Each established conn is a 128 KB bufio read buffer + up to 32 KB write + 2 goroutines + 2 timers, so ten seeding torrents at stock is ~500 conns ≈ 80 MB of buffers and a thousand goroutines, against a 256 MB target. Config keys were considered and rejected: raising them past what the host has does not buy throughput, it buys the OOM killer, and a machine with room to spare should run an external client that owns its own limits. `bounds_test.go` asserts each value is *below* the upstream default, so a future anacrolix bump cannot silently turn a cap into a widening.
- **Uploaded bytes are persisted per torrent (`TorrentSession.uploaded`) and ratio is read off `uploadedBase + this process's counter`.** anacrolix's `BytesWrittenData` starts at zero every boot, so a ratio built on it alone forgave everything a torrent had already given back and a `seed_ratio` target receded on every restart — `completed_at` had always been persisted, so the seed-*time* limit worked and only ratio silently didn't. `enforceOnce` writes the total **before** its `Info()`/`wantedMissing`/paused/seedStopped gates, since incomplete and paused torrents upload too and this minute tick is the only pass that runs. `Engine.Close` flushes the counters, so only a hard kill loses up to a minute of upload; the alternative is a write on every stats read.
- `e.rates` keeps working on the **session** counter — it is a delta, so folding a constant base in would change nothing but the first sample after boot.
- **The engine owns its own peer sockets — `DisableTCP` + `ListenPacket` — instead of letting anacrolix create them**, because `Client.LocalPort()`, and every tracker announce behind it, reads `cl.listeners[0]`: an anacrolix-created listener has no removal path (`AddListener` only appends), so adding a replacement on a new port would leave the announce still naming the old one. `rebindablePacketConn` and `rebindableListener` are always rebound in step, both landing on the same port — the design leans on that agreement, not on `cl.listeners` ordering staying stable. `rebindablePacketConn.ReadFrom` must swallow the `net.ErrClosed` a rebind produces on the retired socket and retry on the replacement, because `utp.Socket` reads this conn in a loop and treats any error as a dead socket, tearing the uTP stack down for good. A rebind is otherwise selective in what it disrupts: TCP peer connections are each their own kernel socket and survive it; uTP connections all ride the one packet conn and don't.
- **`client.Close()` does reach the packet conn.** anacrolix wraps the `net.PacketConn` handed to `ListenPacket` inside a `utp.Socket` and appends that socket's `Close` to `cl.onClose`, so `Engine.Close`'s own `packetConn.Close()` call is a genuine double-close — safe only because `rebindablePacketConn.Close`/`rebindableListener.Close` are idempotent. The TCP listener is different: `AddListener` only appends to `cl.listeners`, and its doc says the caller owns closing what it registers that way, so `Engine.Close`'s `listener.Close()` is the only thing that ever closes it. `rebind` binds the replacement socket before closing the retired one, so asking a socket to rebind to the port it already holds is a real `EADDRINUSE` — `movePeerSockets` (the locked half of `SetListenPort`) guards each socket individually rather than checking only whether the pair is already correct, which is what lets a *manually retried* call converge on a partial failure (listener moved, packet conn still stuck) instead of wedging on the already-correct socket. Nothing retries automatically, though: the only caller is gluetun's `VPN_PORT_FORWARDING_UP_COMMAND`, fired once per port rotation with no retry of its own, so a partial failure persists — announcing the old port while the TCP listener sits on the new one — until the next rotation or a restart. It's logged at `observability.LevelCritical` with both ports for that reason.
- **A completed port move forces a DHT re-announce; trackers get nothing.** `SetListenPort` ends in `announceToDHT`, which calls `Torrent.AnnounceToDht` for every torrent on every `Client.DhtServers()` entry. That reads the peer port live (`incomingPeerPort`) at announce time, so an announce issued after the rebind carries the new port with no extra plumbing — and unlike the tracker side it is a *real* forced announce. There is none for regular trackers in the pinned anacrolix: `ModifyTrackers` used to force one and no longer does (`torrentRegularTrackerAnnouncer.Stop` is a no-op, and both `modifyTrackers` and the client-level dispatcher key their state by infohash, so restarting a running announcer is a no-op too — measured at 0 announces in 5s against a local tracker). A private tracker can therefore advertise the dead port for up to its whole interval; DHT is the half that can be refreshed at once. The locked rebind lives in `movePeerSockets` **so the announce runs with `e.mu` released** — `AnnounceToDht` takes the anacrolix client lock, and this file otherwise never holds `e.mu` across a call into anacrolix. An empty `DhtServers()` (`entry.DisableDHT` → `cc.NoDHT`) is a configured no-op, and a nil client is the shape `SetListenPort`'s own specs build.
- **`DisableTCP` means the engine must supply its own TCP dialers, on both paths.** `New` calls `client.AddDialer` right after construction: source-bound to `bindIP` (`tcp4`/`tcp6` picked by `bindIP.To4()`) when `bind_interface` is set, a plain unbound `tcp4` + `tcp6` pair otherwise. `cl.dialers` is populated only from sockets anacrolix itself created, so skipping either branch leaves every outbound peer connection uTP-only, silently — no error anywhere names the missing dialer.
- **The unbound path additionally sets `cc.DisableIPv6 = true`** so exactly one UDP network exists — one `ListenPacket` call, one `utp.Socket`, one DHT server, rather than two racing to read the same packet conn. The cost: anacrolix rejects every inbound IPv6 peer and skips `udp6://` trackers, while the unbound `tcp6` dialer above still dials IPv6 peers outbound.

## Import verification & holds
- The importer verifies a probed source against the release claim before any transfer (`verifyFile` in `internal/importer/verify.go`, a pure function) and parks a failing record at `download_record.status = held` with a `hold_reasons` JSON column, returning **nil** — a hold is an outcome, not a failed attempt, so `import_attempts` doesn't move.
- Four checks, each producing one `{file, check, expected, actual}` reason: `corrupt` (probe error — nothing else is evaluable, so it is reported alone), `resolution`, `duration`, `codec`. Plus `always_ask` (`library.probe.always_ask`), which holds an otherwise-clean import and needs no probe, so it fires with ffmpeg off. A source that cannot even be resolved (`ErrNoMedia`) fails the import as a counted attempt instead of holding.
- **Resolution is bucketed by WIDTH**, not height: scope aspect ratios crop height (1920×800 is 1080p). ≥3200 → 2160p, ≥1800 → 1080p, ≥1200 → 720p, else 480p. Only a bucket *below* the claim holds; higher never does, and the claim parses from the payload basename with the release title as fallback — only when both parse nothing is the check skipped. `4K` and odd casing normalize to their bucket.
- `duration` compares against the metadata runtime (movie `runtime`, episode = its show's) scaled by `library.probe.min_duration_ratio` (default `0.5`); runtime `0` skips it. `codec` holds when the profile's `allowed_codecs` is non-empty and the probed video codec isn't in it (case-insensitive); empty = any codec.
- A probe that never ran (ffmpeg disabled/missing) verifies **nothing** — nil info with a nil error must not read as corrupt.
- Season packs are verified **before anything moves**, but only over the files the import actually plans to take: the importer builds a per-file plan first (episode match, existing-file lookup, then probes every matched file — the probe result feeds the `replace_mode` decision via `quality.ReplacesFile` under `upgrades`, since the incoming width/codec come from it) and only runs the verdict/hold-reason pass over the files that plan marked for import — a corrupt file belonging to an episode the import was never going to touch doesn't hold the record. A file matching no episode isn't probed at all. Under `replace_mode: all` the planned set is every matched file, so that mode verifies whole exactly as before. Any planned file's reasons still hold the entire record, reasons itemised per file — importing part of the *planned* set and holding the rest would split a season across two states.
- `POST /api/v1/downloads/{id}/resolve` (admin) takes `{action: import|regrab|delete}`. `import` sets `verification_bypassed` and re-enqueues, so the re-run imports as-is; `regrab` and `delete` both remove the torrent **with its files** and fail the record, differing only in whether the movie goes back to `wanted` for another search. Episodes revert to `wanted` on both. An unknown or missing action is a 400, and 409 when the record exists but isn't held; the queue verbs (pause/resume/cancel) answer 409 on a held record, pointing at resolve. Single-file replace imports verify **before** the existing file is replaced, like packs.
- Held records appear in the live queue (`ListActiveDownloadRecords` includes them) with `status: "held"` and `hold_reasons`, which is what the SPA's ResolveDialog renders.
- Deliberate limits: no release blocklist, so a re-grab may re-find the same release; holds are per-record even for packs; `hold_reasons` is cleared on resolve rather than archived.
- Runtime image ships static `ffmpeg`/`ffprobe` binaries (`mwader/static-ffmpeg`, digest-pinned) copied into `/usr/local/bin` — the distroless final stage has no package manager to `apt`/`apk` install into, and static-ffmpeg's binaries have no external deps so a bare `COPY --from=` is enough.

## Adopting a manually-added torrent
- `download.AdoptManualTorrents` (`internal/download/adopt.go`, run on the `download_monitor` tick) matches every untracked seeding/completed torrent the enabled clients report against the library, and either auto-imports or files a `pending` proposal. qBittorrent's `ListTorrents` filters to the `streamline` category and the builtin engine only holds what streamline added, so nothing an operator didn't put there can reach this pass.
- **A release matching nothing in the library becomes an `unidentified` proposal, not a silent skip.** It is the one proposal carrying **no media edge** (both `DownloadRecord` edges are optional and `events.hooks` skips an owner-less row rather than failing the mutation, so the row inserts cleanly). That last part was a claim before it was true: `downloadRecordOwner` fell through to `m.IDs(ctx)`, which ent refuses outright on `OpCreate`, so the hook failed the insert and *every* unidentified adoption was dropped with one `adopt: persist failed` line at WARN. A create carries its edges in the mutation or not at all — there is no stored row to fall back to — so `OpCreate` now returns the empty owner before that query. Dropping it was what made adding a torrent for an untracked title a dead end: no record, no proposal, nothing above debug in the log, and no way to point at it afterwards. Every `ok == false` from either classifier lands here, so no path through the loop is silent any more.
- `POST /activity/pending/{id}/identify` `{kind, provider_id}` (admin) is how it gets a title: add the movie/series when the library lacks it, then link the record. **Both `movie.GetByTMDBID` and `db.FindTVShowByTVDBID` report "not in the library" as a nil row with a nil error** — testing the error instead of the row is a nil deref, and a mock returning `ent.NotFoundError` hides it through a green suite (it did, and the panic surfaced on the first real click). The anchor episode comes from `download.AdoptionEpisode`, shared with `classifyEpisodeAdoption` so a hand-identified pack lands on the same episode the automatic path would have picked. 409 when the proposal already carries media; 422 when the chosen show has no counterpart for the season the name claims.
- **A pack proposal links one anchor episode, and `GET /activity/pending/{id}/preview` is what stops that from being the whole story.** `AdoptionEpisode` picks the first episode the release can *fill* (a whole-series pack names no season, so `parsed.Season` is 0 — the specials, not "unknown" — `AdoptionEpisode` orders the numbered seasons first with specials last, and `packAnchor` takes the first episode holding no file, falling back to the first episode in scope when every one already does — the pack is then an upgrade); the preview then reads the torrent's own file list off its download client and buckets every file the way the importer will: `imports` (holds no file), `upgrades` (holds a file this release beats), `keeps` (its file wins, or no profile ranks it), `unmatched` (a count — extras, or a name the parser cannot read). It applies the importer's ext/size/sample filters and reaches the per-file verdict through the *same* `qualityctx.Replaces` `takesPackFile` uses, so the counts cannot promise what the import then skips. What it cannot mirror is the probe — the files are still in the client — so `upgrades`/`keeps` are a name-and-size estimate and the SPA says so. 409 for a proposal with no episode edge, 422 `connection_failed` when the client cannot be listed.
- **The preview decides the pack row's label and its actions**, which is also what repairs a record identified before the anchor fix without migrating anything. The label drops the anchor episode (`Kaamelott · S03`, or `· N seasons`), since naming one episode read as a proposal to import that episode. And the two actions stop being alternatives: a pack can both fill gaps and beat files, so **Import** shows when `imports` is non-empty and **Replace** when `upgrades` is, each hidden when it would do nothing. `has_file` is not consulted for a pack at all — it is the *anchor's*, so it once offered Replace on a pack that was purely filling gaps. Both buttons are disabled while the preview is in flight so neither changes under the cursor; a single-episode record keeps the old `has_file` either/or.
- **`ReplacePending` raises `replace_mode` to `upgrades` and deletes no media file** (it may still remove the *old torrent* when the body asks with `remove_old_torrent`, best-effort and only for a distinct hash). It used to pre-delete the matched media's file in the handler, which was wrong three ways: on a pack it deleted the *anchor's* file — a handle, not necessarily anything the torrent holds — while the record stayed `replace_mode: none`, so the importer then skipped every other episode that had a file; and on every shape the delete ran before anything was probed, so a held import had already destroyed the only copy on disk, the exact ordering `importSingleEpisode`/`importMovieRecord` go out of their way to avoid. `upgrades` rather than `all` because a pack proposal is not a release anyone inspected: `quality.ReplacesFile` decides per episode against that episode's own file, so a better file already there is kept. A movie or single episode has no second opinion to reach, so the importer's `!= none` check reads it as the plain overwrite it is. Replace can therefore legitimately do nothing — which is why the row hides it when `upgrades` is empty.
- Identify leaves the record `pending` — naming it is not accepting it — so the existing Import/Replace/Ignore still decide. `ImportPending`/`ReplacePending` answer **409** on a record with no media edge, since there is nothing to import into or replace. `PendingItem.media` is absent for these and is what the SPA keys the Identify action off; `parsed_title` rides along (present only then) because the raw release name is a useless search seed.
- Adding a series through identify uses `tvshows.Add` exactly as a hand-add does, so the show arrives monitored and the missing-episode search will start filling its other seasons. That is the same consequence as adding it yourself, deliberately not special-cased.
- The RBAC table (`internal/server/restapi/rbac.go`) is **deny-by-default and keyed by operationId** — a new endpoint 403s with `operation missing from the RBAC table, denying` until it is listed there.

## Media server refresh
- The importer calls `mediaserver.Dispatcher.RefreshAll(ctx, kind, libraryPath)` after every successful import, `kind` being `movie` or `series`. Jellyfin/Emby ignore both args and refresh everything; Plex rescans one section, so the kind picks between `library_section` and `library_section_tv`. Passing only the path meant an episode import poked the *movie* section, and `library_section_tv` was dead config outside the play-on deeplink.
- **Plex's path match is a fallback, not the mechanism.** `findSection` compares `libraryPath` against the section locations Plex reports, which are Plex's *own* mount paths: in any containerised install ours is `/srv/streamline/movies` and Plex's is `/data/movies`, so the match finds nothing and the refresh used to fail with `no section found for path …` — imports landed and nobody's library ever saw them. On a miss it now WARNs and refreshes every section, matching what Jellyfin already does. Setting `library_section`/`library_section_tv` skips the lookup and scopes it back to one.
- Both keys are reachable from the settings form; discovery reports each section's Plex type, so each picker only offers sections of the type it names.
- **Discovery has two endpoints, and the saved-server one is not optional.** `POST /media-servers/discover` takes `{server_type, host, api_key}` and serves the *create* form, where the row does not exist yet. A saved server's token never reaches the browser (the read view carries only `api_key_set`), so the edit form has no key to send and that endpoint would be handed an empty one — which is why `POST /media-servers/{name}/discover` (`DiscoverSectionsByName`, mirroring `TestByName`) runs against the stored secret instead. Before it existed the edit form's Discover button was permanently disabled behind `!api_key`, so section keys were unobtainable for any configured Plex server.
- Discovery always fills the pickers — `discover.onSuccess` only assigns `sections`, and the section `Select`s are marked `readOnlyExempt` so they stay usable under `read_only` even though the rest of the form is locked. What `read_only` blocks is *saving*, not picking, so the pickers stay useful for figuring out which section is which. A separate "Show config snippet" button (visible once `lock() && sections.length > 0`) opens `PlexSectionsModal`, which shows the section keys the operator picked plus a paste-ready YAML block to commit by hand — same shape as `PlexCredentialsModal` for the PIN token. Discovery and PIN sign-in deliberately skip `readOnlyLock` — they only read remote state (see the note on the function itself).
