# Config surface

> **Read before touching** `internal/config/`, the `/config/*` handlers, `api/config.schema.json`, or any config-backed resource CRUD.
>
> **Covers** — which sections are patchable at runtime and which are file-only (and why the trust boundary is file-only), the `/config/system` three-block case, the bounded-integer and duration guards, and the name-keyed YAML resources (media servers, download clients, indexers, quality profiles).
>
> **Load-bearing** — adding or removing a config field means `defaults()` **and** `api/config.schema.json`; `narrowUint8` and `checkDuration` must reject before conversion, since nothing validates a request body against the spec.

## Runtime config surface (`/config/*`)
- Seven sections are readable and patchable: `/config/{auth,library,ffmpeg,download,metadata,system,transcoding}`, all admin-only, all partial-patch (a nil field is left alone), all echoing the section's new state. Everything else in the config is file-only and needs a restart. `docs/wiki/Configuration-Reference.md` holds the operator-facing table of which key lives on which settings page; keep it in step when a key moves in or out of this surface.
- **What is deliberately *not* here.** The trust boundary — `auth.mode`, `auth.trusted_networks`, `auth.trusted_role`, `server.trusted_proxies` — is file-only for the same reason `oidc[].allow_admin`/`email_linking` are: a key an attacker could reach through the API is a key the API can be made to grant. So are the seed-admin block and every session/API secret. `data_dir` and server host/port are out because they decide what the process opened before it could serve a request.
- **`/config/system` is the one section spanning three config blocks** (`log`, `otel`, `events`) because it is one question — what the server records about itself — and none of the three is big enough to be its own endpoint. It also mixes hot and cold: `events.retention` is read per cleanup tick, while the log handlers and OTLP exporters are built once by `observability.Setup`. `UpdateConfigSystem` therefore compares `Log` and `OTel` **struct-wise** against the pre-update config and only then calls `restart.Mark()` — a retention-only patch must not ask for a restart it does not need. `LogConfig` is one all-optional schema serving both the view and the patch (like `ProbeConfig`), so `logPatchFromAPI` is what keeps a `{"log":{"app":{"level":...}}}` body from flattening its siblings.
- **Every write logs a diff of what changed.** `config.Update` renders the flattened before/after (`changedKeys` in `internal/config/audit.go`) as `key: old → new` on the `config saved to disk` line. Who is free — `contextEnrichingHandler` attaches `user.id`/`user.email` — but *what* was recorded nowhere, so "who turned `download.selective_files` on last Tuesday, and what was it before" had no answer: the config file is typically not in version control. The diff is taken **before** `stripEnvLayerLocked` thins the write, so it describes what the admin asked for rather than what survived the env layer. Anything whose key contains `password`, `secret`, `api_key` or `token` renders as `changed` with neither side printed — `secretKeyParts` in the same file, and it deliberately catches `session_secret_file` too.
- **`otel` carries `insecure`, `sample_ratio` and `environment` alongside `endpoint`.** All three are file-only and all three go through `defaults()` *and* `api/config.schema.json` like any other key. `sample_ratio` is validated `min=0,max=1`; `observability.Setup` skips its own `WithSampler` entirely when `OTEL_TRACES_SAMPLER` is set, because passing the option at all makes the SDK stop reading the standard variables — the comment that used to promise otherwise was wrong.
- **`torrent_listen_port` is not on this surface and must not be added.** It is authored by a VPN tunnel, not by an operator: `PUT /torrents/listen-port` moves the running engine's sockets and persists nothing, so a restart falls back to `STREAMLINE_TORRENT_LISTEN_PORT`. The SPA affordance lives on the Torrents page (live engine state) rather than a settings form for exactly that reason — and it exists because gluetun's `VPN_PORT_FORWARDING_UP_COMMAND` fires once per rotation with no retry, so a partial move needs a human re-issue.
  - **`DownloadClient.listen_port_override` is what stops the builtin form from lying.** Three keys name the peer port, and `BuiltinDownloadClient` resolves `torrent_listen_port` over the entry's own `listen_port` — but `ListDownloadClients` converts the raw `c.DownloadClients` entries, so the form was showing, and saving with a 200, a value the engine never binds. On the deployment the override exists for. The view now reports the override (builtin only, non-zero only) and the form goes read-only behind it. `port_bound` is a different signal and both are wanted: it is the live socket off `client.LocalPort()`, present only while the engine runs, while the override names the *cause* and survives the engine being down.
- **The file-only keys are reported read-only on `SystemInfo`, not left invisible.** `sysinfo.Snapshot` carries the trust boundary, the bootstrap block and the generated values so Settings → General can say what is in force — otherwise the only way to know is reading the YAML on the host, which a container deploy makes awkward. `GetSystemInfo` is already `roleAdmin`, which is what makes this safe; it must stay that way. Secrets are never reported as a value: the seed-admin password as a **source** (`sysinfo.secretSource` → file/config/unset, applied in `sysinfo.Collect`), the session and provider secrets as their `*_file` path or nothing. `fillFileOnlySettings` is the one place the Snapshot's file-only block reaches the API. The block also carries `OTelEndpoint`, `LogLevel` and `LogFormat` — the endpoint reported **even when empty**, since "export is off" is the answer to "why is nothing arriving in the collector" and omitting it hides the finding.
- **`library.{movie,series,download}_path` are read-only in `LibraryConfigView` and absent from `LibraryConfigPatch`.** `config.LibraryPatch` still carries them because `pathmigrate` writes them — it rewrites every stored path in the DB and repoints the root afterwards. A second, plain-PATCH door would strand every path the library already recorded. The view carries them anyway so the settings page can show where the library lives and link to Advanced.
- **`narrowUint8` is the guard on every bounded counter** (`max_grab_failures`, `import_max_attempts` 1–255; `drift_grace_ticks`, `lockout.threshold` 1–20/255). Nothing validates a request body against the spec's `minimum`/`maximum` — there is no request-validation middleware — and `uint8(300)` is 44, a value the config's own `min=1` / `max=…` tags then happily accept. The narrowing has to reject before the conversion, not after.
- **`checkDuration` guards every Go-duration key** (`session_ttl`, `lockout.{window,duration}`, `no_match_cooldown`, `selection_grace`, `events.retention`). `Config.Validate` marks these `required`, which is only non-empty — it never parses one. A typo written through the API therefore lands on disk and surfaces much later, as a job silently falling back or not running at all.
- **`/config/metadata` writes are restart-required and the handler says so.** `metadata.NewTMDB`/`NewTVDB` read the four keys once, when `wire.go` constructs the clients, so `UpdateConfigMetadata` calls `restart.Mark()` on a real change (comparing the whole struct — re-sending stored values raises nothing) and the view reports `restart_required` off the same process-wide flag ffmpeg and OIDC use. Keys are write-only: the view carries `*_set` and `*_file_managed` booleans, a blank key preserves the stored one (so there is no way to *clear* a key over the API), and setting one inline while the matching `*_file` is configured returns `ErrSecretFileManaged` — mirroring `UpdateIndexer`.

## Config-backed resources
- Media servers, download clients, indexers, and quality profiles live in the YAML config (NOT ent/SQLite), name-keyed and hot-editable — mirroring `auth.oidc[]`. Top-level lists: `media_server.servers[]`, `download_clients[]`, `indexers[]`, `quality_profiles[]` + `quality_default_profile`. Global grab knobs moved to `library.no_match_cooldown` / `library.max_grab_failures` (the old `library.default_quality` block is gone).
- Helpers in `internal/config/resources.go` (`Find*`/`Enabled*`/`PickDownloadClient`/`ResolveQualityProfile`) + per-family CRUD in `internal/config/mutate_*.go` (`Add*`/`Update*`/`Delete*`, secret-preserve on blank). REST handlers (`internal/server/restapi/handler_{download_clients,indexers,media_servers,quality_profiles}.go`) call config directly — no service CRUD; the indexer/download/mediaserver services keep only behavioral methods (`Test`/`TestByName`/`Grab`/`Feed`/`DiscoverSections`/Plex PIN). Read views hide secrets behind `api_key_set`/`password_set` booleans.
- Endpoints are name-keyed (`/api/v1/<resource>/{name}`); media-server update is `PATCH`, the others `PUT`. Movies reference a profile by `quality_profile` string (empty resolves to the default). DownloadRecord/Movie carry `download_client_name`/`indexer_name`/`quality_profile` string columns instead of FK edges.
- **`torrent_listen_port` is a top-level scalar that overrides the builtin entry's `listen_port`, resolved in `BuiltinDownloadClient()`.** Top-level *only* so the environment can reach it: the env layer maps `STREAMLINE_A__B` onto `a.b` with a single underscore staying literal, so `STREAMLINE_TORRENT_LISTEN_PORT` names it exactly, while nothing inside `download_clients[]` is addressable at all. It exists because the value is authored by a VPN tunnel rather than by git — a per-session forwarded port rotates on every reconnect, so a read-only ConfigMap cannot carry it and a `config.Update` write-back would fail `ErrReadOnly` anyway. Resolving it in config rather than in the engine keeps the engine reading nothing but `entry.ListenPort` (`newPeerSockets` binds it; `newClientConfig` leaves `cc.ListenPort` alone); the engine has no env awareness and no ctx plumbing for it. Read at wiring for the *initial* bind, but no longer the ceiling: `PUT /api/v1/torrents/listen-port` moves the running engine's peer sockets, because the engine owns them rather than letting anacrolix create them. The endpoint persists nothing — a rotation is authored by the tunnel, and these deployments run a read-only config where `config.Update` fails `ErrReadOnly` — so a restart falls back to `STREAMLINE_TORRENT_LISTEN_PORT`. A ProtonVPN tunnel rotates its forwarded port on roughly every reconnect, measured at about one per 2.5 days on the homelab. Builtin engine only; external clients own their own listening port. Adding it meant `defaults()` *and* `config.schema.json`, and the `DumpDefaults` spec fails loudly if the first is missed.
