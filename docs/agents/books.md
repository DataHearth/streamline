# Books

> **Read before touching** `internal/media/book/`, `internal/metadata/hardcover*.go`, `internal/db/book_shelf.go`, `internal/importer/book*.go`, `internal/library/ebookmeta/`, `internal/rss/book_feed.go`, or any `/books/*` handler.
>
> **Covers** — the book-first model and contributions, the two slots, editions and their pick, the Hardcover budget and batching, series lookup, two-phase series add, the shelf query, acquisition, import, adoption, requests and send to device.
>
> **Load-bearing** — a stub is never searched, grabbed or imported; a slot edition a slot points at is never pruned and a refresh never re-points one; every background Hardcover pass stops at the scan reserve; the slot state on the wire and the shelf SQL derive it the same way; nothing is ever written into a book file.

Fourth vertical, **book-first**: `Book` is the root entity and a shelf item on its own, or a volume of a `BookSeries` (`ShelfItem = Book | BookSeries`; a volume is never a shelf item). People are slim `Author` rows (name, sort name, photo source) joined to a book *or* a series through `BookContribution` (`role` author/writer/artist/colorist/cover/translator/narrator, `language` on a series translator; exactly one owner is set, enforced by the writer like `Credit`). **There is no author-follow**: nothing is monitored per author, there is no `/books/authors*` route and no `author` request type, and an `Author` with no contribution left is deleted in the same transaction as the book or series that orphaned it. `Book.author_name` is the display string (authors, else writers, else artists, joined with ` & `, three then ` et al.` — `pick.DisplayAuthor`) and what the naming `{Author}`, OPDS filenames and the indexer query read.

A book carries two independent **slots**, ebook and audiobook, each with its own `*_monitored`/`*_status`/`*_grab_failures`/`*_last_search_at`, a `*_edition` pointer and a `*_replacing_language`; `MediaFile.book_kind` says which slot a file fills. Slot state on the wire is derived (`book.SlotState`, mirrored by the shelf SQL — change one and the other): unmonitored iff not monitored and neither available nor downloading, a paused record is `downloading`, a monitored `wanted`/`skipped` slot is `wanted`. A book's status ignores unmonitored slots and reports `available` until its release date (an unreleased book is never a wanted slot — `ListWantedBooks`, `SearchMissing`, `search-now` and RSS all require `last_refreshed_at IS NOT NULL` and `release_date IS NULL OR <= now`); a series' status looks at its hydrated, released volumes' **ebook** slot only.

**Editions**: `BookEdition` keeps the best Hardcover edition per `(language, publisher, format)` (≤ 40 per book, the winner of every `(language, format)` pair always kept; `metadata.SelectEditions`, pure — a paperback counts as an ebook only for a language with no digital ebook, which is how a comic gets one). A slot points at one; a row a slot points at is **never pruned**, so `edition_id` is stable across refreshes. `internal/media/book/pick` is the shared pure rule set for the database layer and the service: slot pick (preferred language → original → most popular), title derivation (best edition in `preferred_language`, ebook before audiobook, else the original's, else Hardcover's) and the series monitor policy. `Book.title` is never tied to a slot's edition. A **refresh fills a slot that has no edition but never re-points one that has** (a hand-picked edition survives it); `PATCH preferred_language` re-picks every slot without a file; `PATCH format+edition_id` on a slot *with* a file stores `*_replacing_language`, moves the slot to `wanted` (filtered on `available`), and the next grab — `GrabBookRelease` reads the flag — sets the record's `replace_mode = all`, so the importer removes the old file only after the new one is placed and clears the flag in `RecordBookImportSuccess`. A corrected `kind` (a heuristic, `metadata.ClassifyBookKind`) survives a refresh: it is written only when a stub is hydrated.

**Hardcover is called in batches of twenty.** Depth limit 3, 60 req/min through the 1 req/s limiter, 5,000 req/day (`hardcoverDailyBudget`, a UTC-day counter of requests actually sent) with `hardcoverScanReserve` (500) left to adds, refreshes and approvals: the bulk-import scanner and every background pass (`budgetLow`) stop at `Remaining() <= ScanReserve()`. The batch query (`GetBooks`, `hardcover_books.go`) reads up to 20 books with five aliased edition lists in one request — the most popular digital and paper editions, the same two restricted to `library.book_language` (a widely translated book's top editions can all be foreign: *1984*'s French audiobook and paperbacks were in neither), and the earliest; `cached_contributors` carries the makers and a book whose blob names none is read through the `contributions` join (one more request, only for those). A batch Hardcover cuts off is halved and retried (each retry spends budget). Costs: lookup 3 requests (1 with `type=book`; `type=series` is still 3: book search, series search, the batch below), memoised 5 min per normalised query, with the batch memoised 5 min on the sorted series-id set (`Hardcover.seriesLookups`) and `Service.Lookup` itself uncached so `markAdded` reads the library on every call; lookup detail 1 (book) or 2 (series: skeleton + one batch of the first six volumes), memoised 10 min; add book 1; **add series `1 + ceil(N/20)`, of which two are on the HTTP request**; refresh book 1; refresh series `1 + ceil(N/20)`; scheduled refresh `ceil(B/20)` per ≤ 100 stale books plus a series pass for ≤ 5 stale series; each refresh of standalone books adds one request when a format holding a file follows an edition (`ExistingEditions`, every such edition of the batch at once). A book Hardcover no longer returns is a `book_removed` metadata change, and an edition a format holding a file follows that Hardcover no longer has is an `edition_removed` one (`docs/agents/metadata-changes.md`); following it clears the format's edition, which the next refresh fills from the pick rules, its file kept. A `429` or an exhausted day is `*metadata.RateLimitedError` wrapping `metadata.ErrRateLimited` and never sets `hardcover_auth_warn`; add, refresh, lookup and approve answer `429` `code: rate_limited` with `Retry-After`, no key answers `503`, and `RefreshStale` stops its tick at the first one and returns nil. `streamline.metadata.hardcover.requests{outcome}` counts it.

**Series lookup finds a series through its books.** Hardcover's series search matches only the series name, so a series searched by a translated title was invisible. The book hits whose title or any alternative title folds equal to the query (`library.TitleMatchesStrict`) or contains every query token contribute their `series_ids`; those ids are unioned with the series-search hits and read in **one batched request** (`GetSeriesLookup`: name, slug, `is_completed`, counts, author and up to 50 `book_series` rows ordered by position then readers, so each position's winner survives the limit, with `book{id users_count compilation cached_image}`, not `image`, which is a relation past the depth limit). A series with `primary_books_count = 0` is dropped, and so is a book hit with neither a credited maker nor a cover (a stray row nobody can tell apart, which the importer would hold for want of an author anyway). The cap (20) never drops the top group: name-matched series plus series reached through a book whose title **equals** the query. A series reached only through a book holding the query's words goes after the books, because a broad query ("star wars") reaches dozens and would otherwise push out every book. Each hit carries `cover_book_ids` (the winners at the first three positions by the add path's rule, `winnersByPosition`, **that have a cover** — a series that numbers none, or none with a cover, fans its most read unnumbered books instead, read in the same request as `loose` — registered with `artwork.Remember(KindBooks, …)`), `matched_title` (set when the matching book title differs from the series name, shown as `via « … »`) and `slug`; the lookup detail picks its volume preview with the same winner rule from the skeleton. `BookSeries.hardcover_slug` is stored on add and refresh (an empty slug clears it); the series page and the lookup panel build `hardcover.app/series/{slug}` from it (a book links `hardcover.app/book/{id}`, since `/books/{id}` is a 404). A library series' fan of covers is `cover_ids` (`db.SeriesCoverIDs`: the first three positioned, **hydrated** volumes in position order — add, hydrate and refresh keep only each position's winner, so these are the lookup fan's books once the series is hydrated; the shelf reads them in one extra windowed query per page), drawn by the SPA's `SeriesCover`.

**Series add is two-phase.** Phase one (synchronous, the 2 requests): the skeleton (`series` + numbered `book_series`, one request) and the first 20 volumes; one transaction writes the series, those volumes fully hydrated and a **stub** `Book` for every other position (`last_refreshed_at NULL`, placeholder title `"{Series} #{n}"`, no editions, slot flags from the series policy). The series answers `hydrating: true`. Phase two: one process-wide worker (`HydrateSeriesInBackground`, `defer RecoverPanic`, span `book.hydrate_series`) drains stubs in batches of 20, each volume in its own settle step (series policy against the series' creation time, the series' chosen `(language, publisher)` edition); a stub Hardcover no longer knows, or that is a compilation, is deleted when it holds no file. **A stub is never searched, grabbed or imported** (the importer holds the record; `GrabBookRelease` answers `ErrNotHydrated`), and restart recovery is free: `RefreshStale` hydrates stubs *first*. A volume already in the library as a standalone book is **adopted** into the series (its data kept); one in another series is skipped and logged. Series `monitor` (`all`/`future`/`none`, stored) applies to each volume's **ebook** slot only; `future` is measured against the moment of the patch (or `BookSeries.create_time` for volumes a refresh finds). `BookSeries.quality_profile` is written through to every volume, and resolution for a book is `Book.quality_profile` → its series' → **the default for the book's kind** (`book_quality_default_profiles: {novel, bd, comic, manga}`, `config.ResolveBookQualityProfile(name, kind)`, `book.ProfileFor`). `PATCH series edition` takes a label from `BookSeries.editions` (`"{language in its own name} · {publisher}"`, ordered by volumes covered) and re-picks only the volumes **without** an ebook file; volumes with one keep file and edition.

Metadata is Hardcover (GraphQL, `metadata.hardcover_api_key` or `_file`): **the key is optional** — without it `wire.go` leaves the provider nil, the service answers `ErrNotConfigured`, the handlers answer `503` and the add page says Hardcover is not configured. Every Hardcover-dependent handler (search, lookup, add, refresh, request approve, import start and commit) builds that 503 through `errHardcoverUnavailable` (`restapi/hardcover_errors.go`): `code: hardcover_not_configured` for a missing key, `code: hardcover_key_rejected` when Hardcover answered 401 (the import operations can only report the first; a key rejected mid-scan surfaces after the fact). The key is settable through `PATCH /config/metadata` like TMDB/TVDB, restart required. `library.book_language` (ISO 639-1, runtime-editable on Settings → Library, default `en`) seeds `Book.preferred_language`; `library.book_series_naming` (**not** `library.series_naming`, which is the TV template) names an ebook volume of a series (`{Author}/{Series}/{Series} - Vol. {Volume:02}`), `ebook_naming`/`audiobook_naming` gain `{Language}`, `{Series}`, `{Volume}`, and `{Title}` is the slot edition's title. Covers and creator photos come through the posters proxy under the `books` and `authors` kinds, fetched in the background from the CDN address the Hardcover payload already carried (never a Hardcover request); lookup art is `artwork.Remember(KindBooks, id, Source{URL})` as lookup and detail responses are served.

**The shelf** (`GET /books`, `internal/db/book_shelf.go`) is one raw-SQL `UNION ALL` of standalone books and series — ent cannot union, and merging two paged ent queries gives wrong deep pages — with the filters applied inside both arms and the derived status filtered, ordered and paged outside; counts are faceted (each facet counted with the others applied and its own left out, each with an `*_total` row, authors keyed by folded creator name so homonyms merge). Live download progress comes from `download.Queue` matched to the book's active records (`ListActiveBookRecords`); the download manager is untouched.

**Acquisition**: `ParseBookRelease` (bare `MP3`, `M4A` and `FLAC` without audiobook context are music, never a book; `CBR` is a comic container only when the name carries no audio token and no `CBR 64`-style rate; a stated audiobook rate lands in `BitrateKbps`; `Language` from the design's word list, `Volume`/`VolumePrefix` from `tome|volume|vol|t|v|#` + digits, fractional allowed; ranges and `intégrale` are collections) with `ScoreEbookRelease`/`ScoreAudiobookRelease` (and `Judge*` for the reject reason), `indexer.Manager.SearchBook` (7000+7020 ebook, 3030 audiobook; the query is `author + slot edition title (+ year)`, never an alias list). `POST /books/{id}/search` returns **flat** `SearchResult` items (`slot`, upper-case container in `source`, `bitrate_kbps`), both slots merged without `kind`; the grab reads the slot from the release's parsed container and refuses a body whose `slot` disagrees (`grab_rejected`), `kind` and the body slot disagreeing is a `400`. **Automatic paths only** skip a release tagged with a language other than the slot edition's (`book.WrongLanguage`); interactive search never filters on language. `SearchMissing` walks standalone slots one by one and groups series volumes: `searchSeriesVolumes` runs **one** query per series, takes each volume's best accepted match by parsed `Volume`, and makes at most 3 per-volume fallback queries; `search-now` for a book or series runs the same pass in the background and answers `202 {queued}`. Both the music and book services export `ErrNoQualityProfile` (`422`, `code: no_quality_profile`).

**Import**: the book importer places one best-format file for an ebook and the whole folder, original filenames kept, for an audiobook (`library.BookDestination`), and a failed audiobook import removes what it placed. A record is **held** (`Check: metadata`) when the book is an unhydrated stub or has no `author_name` — never a wrong path. A volume import flips both the `book` and the `book_series` request. **Rename** (`POST /books/{id}/rename`, `/books/series/{id}/rename`) moves an ebook to its template path and an audiobook folder whole, never onto an existing file.

**Adoption** is `ImportScan.kind=book`: ebooks group by `(dir, stem)`, every folder directly holding audio is one audiobook candidate, identification runs Calibre `metadata.opf` → embedded epub OPF → filename, then `BookByISBN` short-circuits `SearchBooks`; the scanner spends 1 search (+1 ISBN lookup) per candidate and **no** book fetch. The committer prefetches its reviewed books in batches of 20 (`ceil(C/20)` requests) and adds an unknown book **unmonitored** through `AddBook`; nothing is ever written into a book file. Book imports, adoption commits, renames and deletes-with-files refresh media servers (`mediaserver.KindBook`): Jellyfin and Emby rescan, **Plex is skipped** since it has no book library type. Both `StartScan` and `Commit` refuse `kind=book` without a Hardcover key (`book.ErrNotConfigured`, 503) and refuse `mode=rename` first (`ErrRenameUnsupported`, 422): books adopt in place only. A Hardcover 401 mid-scan is scan-fatal rather than a per-row miss: `markScanFailedWithCode` sets `ImportScan.failure_code` (`hardcover_key_rejected`, with a fixed message; `hardcover_not_configured` if the key vanished before the run) so the SPA can link to Settings; every other failure leaves the code empty. Each review row carries `parsed_year` and `size` (stored) and `format`, `file_count`, `source_path` (derived on read from `file_paths`: best ebook format by `quality.EbookLadder`, or the audiobook's dominant extension and common folder). **OPDS** is an extension in its own repository (see `docs/agents/extensions.md`), ebooks only, not part of core. **Automation**: `rss/book_feed.go` gates 7000–7999 to the ebook matcher and 3030 to the audiobook matcher; a release matches a standalone book by `Author - Title` against any of its title forms (display, original, every edition title) and a series volume by the series name plus the parsed volume number, the author optional. **Requests**: `media_type` `book` and `book_series` carry a Hardcover id (two id spaces, hence `media_type` in the dedup key); approving a book adds it `both`, a series `all`, under the reviewer's profile (empty means the family default, a name outside the family answers `422` and the request stays pending).

**Send to device**: `POST /books/{id}/send` mails one ebook to the caller's `device_email` and `POST /books/series/{id}/send` packs a series' hydrated volumes into emails by first-fit under `smtp.max_message_size_mb` (raw bytes before base64, default 25) and 25 attachments each. `book.Sendable` is the one rule for both and for `Book.ebook_send` on the detail: the ebook-slot file whose `quality` is `EPUB`, else `PDF` (EPUB wins), that exists on disk and fits the limit; CBZ, AZW3 and MOBI are not sendable and the reason points at OPDS. The `smtp` section is file-only (restart required, never under `/config/*`), an empty `host` turns the feature off, `password`/`password_file` pair with `excluded_with`, and `tls: none` loads only for a loopback host; `starttls` against a server that does not advertise it fails before AUTH, never falling back to plain. A series send answers `202` with the plan and sends in a background goroutine, so a failing email is **logged (WARN) only**, never surfaced to the API; a single send answers `502 send_failed` with the SMTP reply. Codes: `not_sendable`, `no_device_email`, `smtp_not_configured`, `send_failed`. User docs: `docs/wiki/Send-to-Kindle.md`.
